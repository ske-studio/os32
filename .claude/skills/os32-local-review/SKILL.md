# ローカルモデルによる独立レビュー

レビューは PM が代行できない (`docs/tasks/agents/ROLES.md` §3 の規約 4 番目)。
主レビュアーが尽きたときの**補助**としてローカルモデルを使う。主レビュアーの代わりではない。

## いつ使うか

`ROLES.md` §5 のレビュアー在庫表で、上位 (Codex → Antigravity `agy` → Fable サブエージェント →
Opus 5 サブエージェント) が使えないとき。実力の目安は §「測った結果」。

## 手順

1. **依頼文を書く** (Codex 向けと同じ書式。`ROLES.md` §5 の 5 点):
   対象 / 変更の要旨 / 見てほしい観点 / 判定基準 / 既知の未確認。
   加えて **出力の書式を明示**する (`## 所見` `## 見た範囲` `## 判定`)。
   「到達可能な反例を伴う所見だけが blocker」「1 件見つけて止めない」「推測で行番号を書かない」を必ず入れる。
2. **範囲を絞る**。対象ファイルの合計は **800 行 (約 13,000 トークン) までを目安**。
   票とソースを同時に渡してよい。範囲を広げるほど見落としが増える。
3. **投げる**:
   ```bash
   python3 tools/review_local.py <依頼文ファイル> <対象ファイル>... > out.md
   ```
   接続先とモデルは `REVIEW_HOST` / `REVIEW_MODEL` で差し替える。
   stderr に出る「prompt … tok / eval … tok / … s」は**記録に残す** (次回の範囲決めに使う)。
4. **所見を鵜呑みにしない**。PM が 1 件ずつ反例の到達可能性をコードで確かめてから票に反映する。
   誤検出だったらコードではなくレビュー記録側を訂正する。
5. 票の往復記録に「レビュアー = ローカルモデル (モデル名)」と明記する。
   **どのモデルが見たかを後から追えるようにする。**

## 測った結果 (2026-09-16、qwen3.8:27b Q4_K_M、L4 24GB)

課題: `userland/shell/cmd_script.c` + `sh_args.inc` (791 行) の「入力を黙って切り詰める欠陥」探し。
正解は独立レビュー 5 往復で積み上げた既知の 9 件。

| 指標 | 結果 |
|---|---|
| 所要 | 12,773 トークン投入 → 1,000 トークン出力、**123 秒** (10.4 tok/s) |
| 正確さ | 指摘 **5 件すべてが実在**。作り話・存在しない行番号は **0** |
| 網羅 | 既知 9 件のうち **5 件**。行数上限・`goto` のラベル・ディレクトリ部・確保失敗は見落とし |
| 形式 | 指定どおり (`## 所見` / `## 見た範囲` / `## 判定`) |

**読み方**: 挙げてきたものは信用できるが、挙げなかったことは「無い」の証拠にならない。
`ROLES.md` の「往復は 3 回 + 1」の数え方はそのまま使う。

## 踏むと痛い所 (実地で踏んだもの)

- **opencode は使わない**。この環境では初期化後に要求を 1 度も送らず固まる事例が 2 回、
  文脈があふれて同じ読み直しを 77 回繰り返した事例が 1 回あった。`review_local.py` の直接方式なら起きない。
- **思考を止める** (`think: false`)。止めないと出力枠を思考で使い切り、答えが空で返る。
  OpenAI 互換の口を使うなら `reasoning_effort: "none"` が同じ働きをする。
- **文脈長はサーバー側の既定でしか決まらない**。要求に `num_ctx` を入れても無視される。
  Ollama を起こすときに `OLLAMA_CONTEXT_LENGTH` を渡す。4096 のままだとファイル 40 行で溢れる。
- **Colab では `%env` で入れる**。1 行に詰め込むと**全角スペース**が混入して値が壊れ、既定値に落ちる。
  実際に `OLLAMA_CONTEXT_LENGTH=65536　OLLAMA_KEEP_ALIVE=-1` となっていて 4096 に落ちていた。
  行継続の `\` も改行と繋がって `command not found` になる。
- 推奨の起動 (L4 24GB、64k):
  ```bash
  OLLAMA_CONTEXT_LENGTH=65536 OLLAMA_FLASH_ATTENTION=1 \
  OLLAMA_KEEP_ALIVE=-1 OLLAMA_NUM_PARALLEL=1 ollama serve
  ```
  `NUM_PARALLEL` を絞らないと同じモデルが二重に載って **CUDA OOM でサーバーが落ちる**。
  `KEEP_ALIVE=-1` が無いと 1 分ごとに読み込み直して 60 秒待たされる。
- **Colab のランタイムは作り直される**。`ollama` の実行ファイルごと消えるので、再インストールから要る。
- 量子化を選ぶ。**NVFP4 は L4 (Ada) に演算器が無く**、実効 2 トークン/秒まで落ちた。Q4_K_M で 10〜17 tok/s。
- 創作向けの微調整モデル (uncensored / roleplay 系) は**出力形式の厳守と道具呼び出しが弱い**。
  レビュアーには公式の instruct 版を使う。
