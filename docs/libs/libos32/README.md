# libos32 — システムコール＆スタートアップ・ライブラリ

## 1. 概要

`libos32` は、OS32の外部アプリケーションプログラム（ユーザー空間プログラム）が動作するためのもっとも基盤となるライブラリです。

主な役割は以下の通りです。
1.  **C標準ライブラリ（newlib-nano）のシステムコールブリッジ**: `malloc`、`printf`（標準出力への出力）、ファイルI/O（`open`, `read`, `write`, `close`）などの標準C関数が呼び出された際、それらを `KernelAPI`（システムコール）に変換してOS32カーネルへフォワードします。
2.  **スタートアップ処理（`crt0`）のサポート**: アプリケーションエントリーポイントの初期化、`KernelAPI`ポインタの設定、ヒープ領域のセットアップを行います。
3.  **デバッグシリアル通信**: 開発用のデバッグメッセージをRS-232C経由でホストPC等に送信する補助機能を備えています。

---

## 2. ディレクトリ構成とファイル役割

*   `syscalls.c`
    *   newlib-nano のシステムコールスタブ（`_read`, `_write`, `_open`, `_close`, `_sbrk` など）の実装。
    *   `sbrk` による動的メモリ割り当て（`malloc` / `free` のバックエンド）を管理し、カーネル側から通知されるヒープ限界値（`sbrk_heap_limit`）を超えないように保護します。
*   `dbgserial.c` / `dbgserial.h`
    *   開発およびデバッグ用のシリアルコンソール通信機能。エミュレータ（NP21/W）のRS-232C機能と連携し、ホスト側へのデバッグ文字出力を行います。
*   `pkg.c` / `pkg.h`
    *   パッケージ/インストーラ関連の補助ユーティリティ。
*   `help.c` / `help.h`
    *   コマンドのヘルプ表示などの共通ヘルプテキストフォーマッタ。

---

## 3. 主要なシステムコールブリッジ

`newlib-nano` からの以下の呼び出しを KernelAPI にリダイレクトします。

| 標準C関数 | スタブ関数 | OS32 KernelAPI 転送先 | 備考 |
| :--- | :--- | :--- | :--- |
| `read` | `_read` | `kapi->sys_read` | ファイル・入力デバイスからの読込 |
| `write` | `_write` | `kapi->sys_write` | ファイル・標準出力への書込 |
| `open` | `_open` | `kapi->sys_open` | フラグをOS32内部形式に変換して開く |
| `close` | `_close` | `kapi->sys_close` | ファイルクローズ |
| `lseek` | `_lseek` | `kapi->sys_lseek` | シーク処理 |
| `stat` / `fstat` | `_stat` / `_fstat` | `kapi->sys_stat` / `sys_fstat` | ファイルステータスの取得 |
| `exit` | `_exit` | `kapi->sys_exit` | アプリケーションの安全な終了 |
| `sbrk` | `_sbrk` | (内部でアドレス管理) | `malloc` が使用するヒープ領域の拡張 |

---

## 4. 動的メモリ管理の仕組み (`sbrk`)

外部プログラム実行時、リンカスクリプトによって定義されたBSS領域の終端（`_end`）をヒープの開始アドレスとします。
`malloc` 内でメモリが必要になると `_sbrk` が呼ばれ、ヒープサイズを拡張します。

```c
/* KAPIテーブルからカーネルがセットしたヒープ上限を取得し、オーバーフローを防ぐ */
if (kapi->sbrk_heap_limit != 0 &&
    heap_ptr + incr >= (char *)kapi->sbrk_heap_limit) {
    errno = ENOMEM;
    return (void *)-1;
}
```
ヒープ上限（`sbrk_heap_limit`）は、プログラムロード時に `exec_run` によって実行プログラムのヘッダ情報に基づき動的に割り当てられます。
