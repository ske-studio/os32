# PCMデバイス上のソフトウェアFM音源 — 計画草案

> 状態: 未実装の検討草案。2026-09-28作成（日本時間）。
> 実26／86音源の対応を継続しつつ、FMを持たないPCMデバイスへの拡張を検討する。
> 本文は実装着手、採用ライブラリ、対応機種、リリース時期を確定しない。

## 1. 目的と経緯

OS32では実デバイスのPC-9801-26系／86系を利用する方向で音源対応を進めている。
ユーザーから「FM機能のないPCM対応サウンドボードでも、公開ソースのfmgenを基に
ソフトウェアFM音源で代用できないか」と提案された。

CPUでFM／SSGの波形をPCMに合成し、OS32のPCMドライバから出力すれば実現可能である。
実音源が使える環境では実音源を選び、PCMのみの環境ではCPU資源で機能を補う。
前景1アプリへ資源を集中する[設計草案](DESIGN_APP_FIRST.md)に沿い、
汎用マルチタスクOS化を前提にしない。追加の常時負荷は測定・明示する。

## 2. 現行実装との接点

調査基点: feat/gui、コミット 135b6b5a68f7335eb066fd0322c48f724e313208。
以下は接続候補であり、ソフト音源対応済みという意味ではない。

| 箇所 | 確認した構造 | 拡張候補 |
|---|---|---|
| [drivers/fm.c](../drivers/fm.c) | OPN操作を opn_write() へ集約し、実I/OとBUSY待ちを実施 | レジスタ書き込みのバックエンドを分離 |
| [kernel/snd_engine.c](../kernel/snd_engine.c) | 100Hzの snd_tick() で演奏制御 | 演奏イベントとPCM合成・補充を分離 |
| [kernel/v86_io.c](../kernel/v86_io.c) | 0x188–0x18Fの音源I/Oを素通し | ソフト音源モードでトラップ対象へ切り替え |
| [kernel/v86.c](../kernel/v86.c) | 実音源IRQをゲストへ反射 | ソフト音源タイマーによる仮想IRQへ接続 |

現行の音源所有権移譲も確認し、OS32とVDMが同じ音源状態を書き合わないようにする。

## 3. 対応範囲を段階化する

| 段階 | 提供するもの | 別途必要なもの |
|---|---|---|
| OS32ネイティブ | 既存MML・BGM・効果音をソフトFM／SSGで出力 | fmgen移植、PCM連続再生 |
| VDMの26相当 | DOS側を無改造で利用するためのOPN互換入口 | アドレスラッチ、読出し、BUSY、タイマー、仮想IRQ、検出動作 |
| VDMの86 FM部分 | OPNAのFM／SSGと必要なリズム音源 | 拡張レジスタ、ボード検出、音源データ |
| 86ボード全体 | 86独自PCMを含む互換 | FIFO、制御、割り込み、再生形式とミキシング |

YM2608の合成コアと86ボード全体は同一ではない。
YM2608側のADPCM機能と86ボード側のPCM FIFOを混同しない。
未対応の機能を対応済みとゲストに見せない。
初期段階では全ソフト・全ボード構成の完全互換は目標にしない。

## 4. 境界設計案

1. **音源の入口**: OS32の発音API、VDMの26／86互換I/O。
2. **音源バックエンド**: 実OPN／OPNA、またはfmgenによるソフト合成。
3. **PCM出力**: 合成結果を受け取り、対象ボードのDMA／FIFOと割り込みを管理。

実音源バックエンドはPCM層を経由しない。
ソフト合成コアにはボード固有I/OやVDM内部構造を持ち込まない。
C境界に初期化・リセット・レジスタ操作・時間更新・PCM生成を用意する案とし、
具体的な関数名、KAPI追加、ABIはまだ凍結しない。
OPNA拡張バンクを扱えるレジスタ表現が必要であり、現行の8bit引数を
そのまま全機能向け契約にはしない。

選択はまず明示設定で行い、実音源／ソフト音源／無音を診断可能にする。
自動検出や再生中の切り替えは後段とする。
VDMの入退場時に音源所有権、残留イベント、仮想IRQ、PCMバッファを整理する。

## 5. fmgen移植の調査項目

fmgenはC++製で、YM2203／YM2608等のインターフェースを持つ。
ただし、採用する配布物・版・派生版・ハッシュは未決定。

- 元配布物とREADMEを保存し、変更点を記録する。
- 現行の[制約](CONSTRAINTS.md) [C1] はGNU89である。
  CラッパーだけでC++導入条件が解消するわけではない。
  独立した第三者コードのビルド境界を認めるか、C移植等を選ぶかは実装前に決める。
- 例外、RTTI、静的初期化、new/delete、標準ライブラリ・数学関数・ファイルI/O、
  コンパイラ補助関数への依存を棚卸しする。
- 合成ループだけでなく初期化時の浮動小数点利用も確認する。
  必要ならFPU状態管理を設計し、FPU非搭載CPU対応を自動的に約束しない。
- サンプル型、飽和処理、加算ミックス、ステレオの並び、チップクロックを確認する。
- OPNAリズム用データの要否と入手・配布条件を、コアの条件と別に確認する。

公開版READMEには由来表示、配布、改変表示、README添付、商用組み込み時の
作者合意について条件がある。ソース公開をMIT等と同等とは扱わない。
採用版の条件とOS32の配布形態の整合を確認してから取り込む。
この草案には第三者ソース・音源データを追加しない。

## 6. 時間・割り込み・バッファ

- レジスタ書き込みに単調増加する時刻を付け、書き込み時刻まで旧状態で合成してから
  新しい値を適用する。バッファ単位へ一括丸めすると発音や効果音の時刻がずれる。
- 音源タイマーの進行と、出力済みPCMの再生位置を区別する。
  PCMを先読み生成したことを理由に、ゲストへ未来のタイマーIRQを注入しない。
- タイマーA/B、ステータス読出し、フラグ解除、仮想PICのマスクとEOI、
  ゲスト割り込み禁止中の保留を整合させる。
- 100Hzの演奏制御だけに音源タイマーを丸めない。時間源と次の期限の扱いを設計する。
- PCMはリングまたは複数バッファで供給する。割り込み内では短い補充管理を行い、
  長い合成を割り込み禁止区間へ持ち込まない。
- 前景アプリやVDMがCPUを占有しても補充期限を守れる、上限時間のあるサービス実行経路を
  決める。単に「後で処理する」フラグを立てるだけでは連続再生を保証できない。
- イベントキュー溢れ、アンダーラン、出力停止を数えて診断可能にする。
  過負荷時に無制限にIRQやイベントを溜めない。
- PCMデバイスとVDMのポート／IRQ／DMA資源競合を確認する。
  DMAは現行[HW2]を守り、対象機器のアドレス・アラインメント等も調査する。

## 7. 性能予測と測定

Ra266級は試作候補とするが、実測前のCPU使用率・実用可否は断定しない。
386／486級までソフト音源の常用を保証する計画ではない。

44.1kHz・16bit・ステレオのPCM量は 44,100 × 2 × 2 = 176,400 byte/s。
これは出力データ量であり、FM合成の計算量やPIO／DMA負荷を表さない。

初期比較は22.05kHz／44.1kHz、26相当／OPNA相当で行う。
レートを下げた際の負荷減少と音質・再現性は採用版で測り、比例するとは仮定しない。
例えば512フレーム／44.1kHzは約11.61ms分だが、
バッファ数・キュー・機器内部バッファによって総遅延は増える。

| 測定項目 | 判断に使う内容 |
|---|---|
| PCM生成の平均・最大時間 | 生成期限とCPU余力 |
| FM／SSG同時発音、レジスタ更新密度 | 重い曲・効果音時の負荷 |
| VDMのIN/OUTトラップ、BUSYポーリング | 合成以外のCPU負荷 |
| バッファ残量、補充遅延、アンダーラン回数 | 音切れと最悪時余裕 |
| 長時間の演奏速度と音声／画面同期 | クロック差・時刻丸めによるドリフト |
| VDM・前景アプリの処理時間、入力応答 | 音源追加後に利用目的を満たすか |
| 常駐メモリ、コード量、初期化時間 | 低資源環境での導入コスト |

評価時は機種、CPU、音源コア版、コンパイル設定、PCMボードと転送方式、
レート、バッファ構成、曲・操作、試験時間を記録する。
平均負荷だけでなく、ディスクI/O・描画と重なった最大補充遅延を測る。
既存ベンチマークのMML登録時間をソフト合成速度と読み替えない。

## 8. 実装順序と受入条件案

| 段階 | 作業 | 次段階へ進む条件 |
|---|---|---|
| P0 | PCMボードとfmgen配布物を選定、依存・条件を確認 | ドライバ資料、移植方針、配布条件が明確 |
| P1 | PCM単独で連続再生 | 固定波形を負荷下で再生し、停止・再開とアンダーランを検証 |
| P2 | 26相当FM／SSG合成とOS32 API接続 | MML・BGM・効果音、音色・ノート・リセットを比較し負荷測定 |
| P3 | VDMの26相当I/O・タイマー・IRQ | 音源検出、タイマー駆動演奏、BUSY待ち、入退場が成立 |
| P4 | OPNAのFM／SSG・リズム | 拡張バンク、パン、データ欠落時の扱いを検証 |
| P5 | 86独自PCM互換 | FIFO・割り込み・形式・FMとの混合再生を検証 |

全段階で実音源バックエンドの回帰を確認する。
VDMでは既知の対象曲・ソフトを決めて比較し、音が出たことだけで互換完了としない。
合成をホストへ移す拡張は将来の別検討とし、初期のローカルPCM対応の依存にしない。
