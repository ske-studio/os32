# 実機 (PC-9821Ra266) で OS32 を動かす計画

> 発行: PM (Claude Code `claude-opus-5`、2026-09-17) / 状態: **計画 (2026-09-17)** — 着手は **v3**

対象機: **PC-9821Ra266** (ユーザー所有、2026-09-17 入手)。
着手時期: **v3** ([`../../ROADMAP.md`](../../ROADMAP.md) §2)。**v1.x のあいだは着手しない。**
検証は当面エミュレータで十分というユーザー判断 ([`../network/PLAN.md`](../network/PLAN.md) の「手元にある実機」)。

## 0. この計画の位置づけ

**実機は「いつか動かす」ためのものであって、開発の主戦場をそこへ移すものではない。**
エミュレータでの検証は現に機能している (2026-09-17 の 1 日でカーネル層の不具合を
2 件検出・修正・受入した)。実機は**エミュレータが嘘をついている箇所**を暴くために使う。

## 1. 機体の構成 (調査済み、2026-09-17)

| 項目 | 内容 | OS32 側の状況 |
|---|---|---|
| CPU | Celeron 266MHz | 性能目標 (P100/32MB で超快適) を上回る |
| 内蔵グラフィックス | Trident TGUI9682XGi (2MB) | **HAL に無い。** ただし **PEGC が使えるとユーザーが確認済み**なので当面困らない |
| オンボード LAN | **Intel 82557** (PCI、100BASE-TX) | **使えない。** PCI の列挙が未実装 (§4) |
| 拡張スロット | **C バス 3 本** / PCI 2 本 | **C バスに LGY-98 を挿せば既存ドライバが使える** |
| ディスク | **8GB** (IDE)、健全性は未確認 | **上限未検証** (§2) |
| FDD | **1.2MB / 1.44MB の両方が使える** | 1.2MB は対応済み。1.44MB は未対応だが**要らない** (§3) |
| CD | 使える | **インストーラが既にある** (`userland/system/cdinst.c`、`make iso`) |

出典: [PC-9821Ra266 データベース](https://www.pc-9800.net/db_98/data/pc-9821ra266.htm)。
`docs/hw/` (Bible / UNDOCUMENTED) にこの機種の記述は**無い** (調査済み)。

## 2. ディスク — 8GB は未知の領域

**確かめた事実**: `drivers/ide.c` は **CHS 専用**。`IDENTIFY` で `cylinders` /
`heads` / `sectors` を受け取り (`ide.c:197-199`)、LBA は `dev_blk_read_lba` が
CHS へ変換する。**CHS の上限がそのまま容量の上限になる。**

**現在の作業イメージは 200MB** (`build/nhd/os32.nhd`)。8GB は **40 倍**で、
**試したことがない。**

**確かめていないこと**:

- ATA の `IDENTIFY` が返す幾何の上限 (シリンダ 65,535 / ヘッド 16 / セクタ 63) は
  計算上 32GB 相当まで表現できるが、**実際に効くのは PC-98 の BIOS 側の制限**で、
  機種と設定で変わる。**測らないと分からない。**
- **起動パーティションの位置**。PC-98 の IDE BIOS は起動領域が特定の容量内にあることを
  要求することがある。**先頭に小さく切れば回避できる可能性が高い** (未検証)。

**やること (この順)**:

1. ディスクの健全性を確かめる (ユーザー)。
2. **先頭に小さい区画を切って**起動できるかを見る。8GB 全体を使うのは後。
3. `IDENTIFY` が実機で何を返すかを記録する。**まずそこから。**

## 3. 媒体 — フロッピーから起動して CD から入れる

**確かめた事実**:

| 媒体 | 実装 |
|---|---|
| FD **1.2MB** (2HD、77cyl × 2head × 8sect × 1024B) | **対応済み**。`boot/boot_fat.asm` / `tools/create_fat12_d88.py` / `tools/mkd88.py` がこの形式前提 |
| FD 1.44MB | **未対応**。ツールが 2HD 固定 |
| CD | **対応済み**。`userland/system/cdinst.c`、`make iso`、`fs/iso9660.c` |
| IDE | 対応済み (§2 の上限つき) |

**1.44MB は足さない。** 1.2MB が使えるなら要らない。PC-98 では扱いが別で、
**わざわざ足す理由が無い。**

**段取り**: フロッピーから起動し、本体は CD から入れる。
フロッピーはブートローダだけなら容量が足り、**どちらも既に実装がある。**

## 4. 通信 — ここに一番大きい穴がある

**ゲスト側は問題ない。** リモートシェル (`userland/shell/rshell.c`) は
**シリアル前提で既に動いている** (uPD8251A、IRQ4)。

**穴はホスト側。** 今の道具は**すべて NP21/W の HTTP デバッグ API を叩いている**。
**実際のシリアルポートを話す実装が無い。**

影響するもの:

- `.claude/skills/run-os32/driver.py` (実行スキル)
- `tools/guest_tests.py` (試験ランナー)
- `tools/np21w_mcp/` (レジスタ・メモリ・逆アセンブル)
- `tools/emu_agent/` (ローカル AI のテスター)

**ただし直すのは難しくない。** ランナーは**「ゲストを叩く部分」と「生成・集計する部分」を
意図的に分けてある** ([`../test/TASK_TEST_RUNNER.md`](../test/TASK_TEST_RUNNER.md) §2-2、受入 R7)。
叩く側を差し替えられる形なので、**シリアル版を 1 つ書けば集計側はそのまま使える。**

`tools/np21w_mcp/` の**メモリ・レジスタ系は実機では使えない** (エミュレータの
デバッグ機能に依存)。実機では `kselftest` のカウンタも読めないので、
**自己診断の結果を画面かシリアルに出す口が別途要る。**

## 5. LAN — 手段が 2 つあり重さが違う

| 手段 | 必要なもの | 目安 |
|---|---|---|
| **C バスに LGY-98** | **無し。ドライバは既にある** (エミュレータで M0〜M4 受入済み) | 小 |
| オンボード Intel 82557 | **PCI の列挙** + 82557 のドライバ | 大 |

**v3 で PCI をやるまでは LGY-98 で凌ぐ。**

LGY-98 を挿す価値はもう 1 つある。`docs/tasks/network/PLAN.md` の M4 に
**「NP21/W は受信バッファ溢れを立てず黙って捨てるため、溢れからの復帰経路は
実カードでしか試験できない」**と記録がある。安全網は実装済みだが**発火させたことが無い。**

## 6. PCI — v3 で計画を立てる (ユーザー決裁 2026-09-17)

**確かめた事実**: OS32 に **PCI の列挙は無い**。設定空間を読む仕組みごと未実装。

一度作れば、**このカードも、オンボード LAN も、内蔵 Trident も、同じ入口から見える**。
個別のカードのためではなく**土台として**位置づける。

ユーザーが `1394US2G-PCI` (I-O DATA、ギガビット LAN + IEEE 1394 + USB 2.0 のコンボ)
を検討中。**3 機能の重さはまったく違う**ので、PCI の土台ができても一度には載らない。

| 機能 | 必要なもの | 目安 |
|---|---|---|
| ギガビット LAN | そのチップ専用のドライバ | 大 |
| IEEE 1394 | OHCI 1394 + 上位の転送層 | かなり大 |
| USB 2.0 | EHCI + 下位互換の OHCI/UHCI + 列挙 + クラスドライバ | **最大。単独で 1 つの計画になる規模** |

## 7. Trident — 保留 (2026-09-17)

ユーザーから「実機に合わせて Trident を優先してもよい」という話があったが、**保留**。

**理由**: エミュレータで検証できない。NP21/W のソースに `src/wab/tgui9680.c`
(1,803 行) はあるが、**本体のどこからも呼ばれておらず**、ヘッダ 2 つ
(`tgui9680.h` / `tgui9680_extern.h`) は**中身が 0 バイト**。**書きかけで結線されていない。**
Cirrus は対照的に `cirrus_vga.c` が 247KB あり ini のキーで切り替わり実際に動く。

**書いても動かして確かめられない**ので、「実証はエミュレータで十分」という方針と衝突する。
**PEGC が使えるなら OS32 は実機で動く。** 動かない機種のために先回りしない。

やるなら選択肢は 2 つ。(a) NP21/W 側の `tgui9680.c` を結線する (**OS32 の作業ではない**)、
(b) 実機で検証する前提に切り替える。**どちらも今の方針から外れる。**

## 8. 段取り (案)

| 段 | やること | 前提 |
|---|---|---|
| 1 | `IDENTIFY` の実測とディスクの健全性確認 | 実機に触れること |
| 2 | 先頭に小さい区画を切って**起動する** | 段 1 |
| 3 | **ホスト側のシリアル実装** (ランナーの「叩く側」を差し替え) | 段 2。これが無いと自動で回せない |
| 4 | CD からの導入 | 段 2 |
| 5 | C バスに LGY-98 → LAN、M4 の残り (溢れからの復帰) と M5 | 段 3 |
| 6 | **PCI の列挙** | v3 の計画として別票 |

**段 3 が鍵。** ここまでは手作業で進むが、ここを越えないと**実機での自動回帰ができない**。

## 9. この計画でしないこと

- **v1.x のあいだの着手。** 残りは 8bpp バックエンド (R2) / About / テキストエディタ。
- 1.44MB フロッピーの対応 (§3)。
- Trident のバックエンド (§7)。
- USB / IEEE 1394 (§6)。PCI の土台ができてから改めて。
- **実機の結果でエミュレータの受入を置き換えること。** 両方を取る。
  エミュレータは速くて再現性があり、実機はエミュレータの嘘を暴く。**役割が違う。**
