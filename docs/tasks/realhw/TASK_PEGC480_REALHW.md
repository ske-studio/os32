# TASK_PEGC480_REALHW — 実機の PEGC 640x480 で桁がずれる (v3)

> 状態: **設計 (未着手)**。発行: PM (Claude Code `claude-opus-5-5`)、2026-09-25。
> 対象: 実機 PC-9821Ra266 + 液晶モニター。v2.1 には入れない (ユーザー決定: v3 で良い)。
> 関係: [PLAN.md](PLAN.md) §7、[TASK_FDC_REALHW.md](TASK_FDC_REALHW.md) §9-1 (CUI のずれ、prepare で直した件)、
> `gfx/backend_pegc.c` / `include/pegc.h`。

## 0. 症状 (2026-09-25、ユーザー報告)

- `gfxmode pc98` で GUI を起動 → 正しく表示される。
- `gfxmode pegc` で GUI を起動 → 以前 CUI で出ていたのと同じ「桁ずれ」。ユーザーの見立ては
  「水平同期が合っていない」。
- CUI のずれは 2026-09-24 に、起動時の PEGC 準備で同期を触らないよう変えて消えた
  (`pegc_prepare`、`[pegc] hsync=` 行)。**GUI は今も 480 ラインへ切り替える**ので、ここが残っている。

## 1. 今の 480 ラインへの入り方 (`pegc_init`)

1. `09A8h` ← 31kHz
2. 両 GDC へ SYNC (8 バイト) — 値は `include/pegc.h` の `PEGC_GDC_MSYNC_480` / `SSYNC_480`
3. グラフィック GDC に SCROLL、START
4. `6Ah` ← 69h (800 ライン構成)、21h (拡張グラフィック)

**SYNC の値の出所は NP21/W の `bios/bios18.c`** (エミュレータが INT 18h AH=30h で流す値)。
実機の ROM と同じかは**一度も確かめていない**。uPD7220 の SYNC は書き込み専用で、BIOS ワーク
エリアにも写しが無いので、**読み戻して比べる手段が無い** (`include/pegc.h` の注記)。
NP21/W は同期のタイミングを模擬しないので、値が違っていてもエミュレータでは正しく映る。

## 2. 仮説 (確からしい順)

| # | 仮説 | 根拠 | 見分け方 |
|---|---|---|---|
| H1 | **SYNC の値が実機の ROM と違う** (水平の総幅・帰線区間 — P2〜P5 — がずれていると、液晶は別の画素クロックで取り込み、横にずれる) | 値はエミュレータ由来。pc98 (BIOS の作った同期のまま) は正しい | §3 段 1 で ROM の値を取れば決着 |
| H2 | 書く**順序**が違う (BIOS は表示を止め (STOP 0Ch) てから SYNC、09A8h はその後、など) | 表示中に同期を変えると液晶の自動調整が途中の信号をつかむ | 段 1 で ROM の OUT の順序も取れる |
| H3 | `gdc_send` が GDC の FIFO を待たない (ステータス 60h/A0h の FIFO FULL を見ずに 9 バイト流す) | CUI のときに候補 b として注記済み。取りこぼすと SYNC の一部が古い値のまま | 段 1 と独立に、待つ版で試す (§4) |
| H4 | 液晶の自動調整が 31kHz への切り替え直後の信号でロックして、そのまま | 同じ値でも「切り替えた後に自動調整」で直るなら H4 | **次の実機でユーザーが液晶の自動調整ボタンを押す** (段 0) |

GDC のクロック (6Ah 82h〜85h) は 480 ラインでは触らないのが BIOS の定常と見ているが、
これも段 1 の記録で確かめられる。

## 3. 段取り

### 段 0 — 次の実機の回で 1 分だけ見る (実装なし)

- `gfxmode pegc` → GUI 起動 → ずれた状態で**液晶の自動調整**を押す。直るか・直らないか・ずれ方が変わるかを写真で。
- 液晶の情報表示 (OSD) に出る**水平周波数・垂直周波数・解像度**を写真で。31.47kHz / 59.9Hz / 640x480 と
  違えば H1/H2 がほぼ確定する。

### 段 1 — 実機の ROM が流す値を記録する (`v86 -g`、新規)

OS32 には V86 の監視部と、I/O 許可ビットマップで**ポートを選んで #GP で捕まえる**仕組みが
すでにある (`kernel/v86_io.c`)。起動時に保存した実機の割り込みベクタ (`v86_bios_save_real`) で
**実機の ROM の INT 18h** を V86 で呼び、その間の OUT を記録する。

- 捕まえるポート: `60h/62h` (テキスト GDC)、`A0h/A2h` (グラフィック GDC)、`6Ah`、`09A8h`、`68h`、`A4h`/`A6h`。
- 呼ぶもの (Bible 3-2「MATE の拡張グラフィック BIOS」):
  - `AH=30h, AL=08h (31kHz), BH=16h (30 行 / 640x480)` — 480 ラインへ
  - `AH=30h, AL=00h (24kHz), BH=0Ch (25 行 / 640x400)` — 戻す
  - 戻り値 `AH=05h` が正常終了。
- 記録は `(port, value)` の列をそのまま画面とシリアルへ (1 回 100 語程度の見込み)。捕まえた OUT は
  **実機へ通す** (記録するだけ)。GDC の FIFO を読むための IN もそのまま通す。
- CPL0 で動く管理者用の診断 (`v86 -g`) として足し、KAPI は増やさない見込み (要確認)。

実機の回で `v86 -g` を 1 回走らせれば、H1・H2 と GDC クロックの扱いが**数値で**決まる。
エミュレータでも走るので、記録が NP21/W の `bios18.c` と一致することを先に確かめてから実機へ出す
(記録の仕組みの試験になる)。

### 段 2 — 直す (段 1 の結果で分岐)

| 段 1 の結果 | 直し方 |
|---|---|
| 値だけ違う | `include/pegc.h` の 480 / 400 の SYNC を実機の値に。NP21/W でも映ることを確かめる (NP21/W は値から画面の大きさを計算するので、違う値でも 480 ラインに見えるかは要確認) |
| 順序も違う | `pegc_init` と戻し (`pegc_shutdown` 側) の順序を ROM と同じに |
| 機種で値が違いそう | 案 B: 切り替えそのものを **V86 で ROM の INT 18h AH=30h に任せる**。段 1 の仕組みの延長で、画面モードを変える 2 か所 (GUI 起動・終了) だけで使う |

**推奨は「値と順序を ROM に合わせる」まで**。案 B は ROM に任せる分だけ確実だが、
モード切り替えのたびに V86 に入る経路をカーネルに持つことになる。段 1 で機種差の兆しが
出たときだけ進める。

## 4. 段 1 と独立にできる小さな修正 — `gdc_send` が FIFO を待つ

`gfx/backend_pegc.c` の `gdc_send` はコマンドとパラメータを待たずに流している。
uPD7220 のステータス (60h / A0h の READ) の FIFO FULL が落ちるのを待ってから 1 バイトずつ
書く形にする (上限つき、上限を超えたら数えて先へ)。NP21/W では常に空なので回帰はしない。
これ単独で直るかは実機でしか分からないが、害は無い。**段 0 と同じ実機の回に入れる**候補。
