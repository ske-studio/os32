# TASK_SERIAL_VFAST — 実機のシリアルを 115200bps まで上げる (V･FAST + FIFO)

> 発行: PM (Claude Code `claude-fable-5-1`、2026-09-22) / 状態: **実装中** (コーダー Opus 5、worktree `fix/serial-vfast`、基点 efd472f)。ユーザー決裁「着手。ここの改善が開発のきも」

正典: [`PLAN.md`](PLAN.md) §4 (ウェブ情報と資料の突き合わせ)、資料 `docs/hw/undocumented/io_rs.md`、
実機の実測は [`TASK_FDC_REALHW.md`](TASK_FDC_REALHW.md) §9-1。

## 0. なぜやるか

実機 PC-9821Ra266 との会話はシリアル (`tools/rshell_serial.py`) しかない。いまは 9600 で 490 B/s、
38400 に上げても 233 B/s — **回線ではなくゲストの送信ループが上限**。配備・試験を実機で回すには
ここが開発の要になる (ユーザー、2026-09-22)。

## 1. 資料が言っていること

| 事実 | 出典 |
|---|---|
| FIFO モード: `0138h` bit0=1。データ `0130h`、ラインステータス `0132h` (bit2 RxRDY / bit1 TxRDY / bit0 TxEMP、**互換モードの `0032h` とビット位置が違う**)、モデムステータス `0134h`、割り込み参照 `0136h` (bit3-0 要因、bit0=1 で要因なし)。16 バイト。An 一部ロット・Np 以降 | `io_rs.md` 227〜350 行 |
| FIFO 搭載判定: `0136h` bit6 が**読むたびに反転**、bit5 は常に 0 | 同 304〜323 行 |
| V･FAST: `013Ah` bit7=1 で 8253 と無関係に速度。bit3-0: 1100b=9600 / 1000b=14400 / 0110b=19200 / 0100b=28800 / 0011b=38400 / 0010b=57600 / **0001b=115200**。95 年 5 月以降の機種は統合 I/O に 16550 相当を内蔵し V･FAST 可 | 同 352〜380 行 |
| 1st CCU は 8251 のまま (FIFO は前段、16550 は 2nd CCU) | 同 図「RS-232C クロック」 |
| NP21/W は `013Ah` の速度表 (資料と一致) と `0130h/0132h/0134h/0136h/0138h` を実装。`0132h` への書き込みは `0032h` と同じハンドラ (コマンド)。通信速度は模擬しない | `np21w-src/src/io/serial.c` 820〜925 行 |
| 実機 Ra266: 2.4576MHz 系、9600 = count 16、38400 = count 4 で通る | TASK_FDC_REALHW §9-1 |

## 2. 決めたこと

| 決裁 | 内容 |
|---|---|
| 起動時の既定 | **9600 の互換モードのまま** (実機で通った経路を守る)。V･FAST は `serial N` で明示的に入る |
| V･FAST に入る条件 | FIFO 搭載判定が真 **かつ** N が資料の表にある速度。それ以外は従来の 8253 経路 (割り切れなければ WARN) |
| 送信ループ | tick (10ms) を待たない。TxRDY を **1 文字時間 × 2** の予算で `cpu_delay_us` を挟んで見る。予算を超えたら従来の `hlt` へ |
| 受信 | FIFO モードでは IRQ4 ハンドラが `0132h` の RxRDY (bit2) を見て `0130h` から最大 16 バイト取る。互換モードは従来 (`0032h` bit1、`0030h`) |
| 戻し | `serial 9600` で `013Ah` bit7=0、`0138h`=0 → 互換モードへ |
| ホスト道具 | `rshell_serial.py --fast N`: 9600 で `serial N` を送り、N で繋ぎ直して `sync` |
