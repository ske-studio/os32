# FreeDOS(98) ブートデバッグ 現状報告 (2026-05-03)

## 1. 発生していた問題と根本原因の特定

### ① Triple Fault (ia32_panic) の原因
V86モードからカーネルモードへの割り込み（#GP等）の際、特定条件下で `v86_bios_int1b` 内のデバッグ用 `kprintf` がさらに #GP を引き起こし、**無限の #GP 再帰呼び出し** が発生していました。
この再帰によりカーネルスタックが大量に消費され、スタックポインタ (`ESP`) が `0x000F0000` を割り込みました。
`0x000EFFFF` 以下の領域は `PAGE_NOT_PRESENT` (未マッピングまたはR/O) となっていたため、スタックへの Push がページフォルト（#PF）を引き起こし、例外ハンドラが例外を処理するためのスタックすら確保できず **Double Fault (#DF) → Triple Fault (#DF中にさらに例外)** となり、NP21/Wがクラッシュしていました。
**【解決策】** `v86_bios_int1b` 内の `kprintf` 呼び出しをコメントアウトしたことで、このクラッシュは解決しました。

### ② FreeDOS(98) IPL 実行時のハングアップ（画面に何も出ずシェルが起動する問題）
OS32のVFS(`hostdrv`)経由で `fd98_2hd.img` を読み込み、FreeDOS IPLを `0x1FC0:0000` に展開して実行するところまでは成功していましたが、その後OS32のシェルがそのまま起動してしまい、エラー表示などが一切見えない状態になっていました。

この原因は、**OS32の `INT 1Bh` (FDD BIOS) エミュレーションにおけるCHSレジスタのマッピング誤り** にありました。
`v86_disk.c` では、PC-98 FDD BIOS (INT 1Bh) の引数を以下のように誤って解釈していました。
* 誤: `DH` = シリンダ, `CH` = ヘッド, `CL` = セクタ長
* 正: **`CL` = シリンダ, `CH` = セクタ長, `DH` = ヘッド**, `DL` = セクタ

このレジスタの取り違えにより、FreeDOS IPLが「シリンダ0, ヘッド1, セクタ1」を要求した際、OS32側では「ヘッド0」のデータを返してしまい、**FreeDOS IPLが FAT や Kernel.sys のデータとして完全に無関係なゴミデータを読み込んで実行**しようとしていました。
その結果、IPL内でエラーが発生し、IPLのエラー処理ルーチン（`boot_error`）が呼ばれていました。

#### 画面にエラーが出なかった理由
FreeDOS IPLの `boot_error` ルーチンは、`"Err!"` という文字列を TVRAM に直接書き込んだ直後、**`INT 18h AH=00h` を発行してキー入力を待ちます**。
OS32の `INT 18h AH=00h` エミュレーション実装は、**キー待ち要求を受け取るとただちに `1` を返し、V86モードを強制終了してOS32へ復帰する仕様** になっています。
OS32に復帰した後、OS32のシェルが起動しますが、シェルは起動時に `tvram_clear()` を呼んで画面を消去するため、ユーザーの目には **「IPLが実行された直後に何もエラーが出ずにシェルが起動した」ように見えていた** というのが真相です。

## 2. 実施した修正

`kernel/v86_disk.c` におけるレジスタ割り当てを、PC-98 FDD BIOS の正しい仕様（PC9800Bible準拠）に修正しました。
```c
/* CL = シリンダ番号, CH = セクタ長コード, DH = ヘッド番号, DL = セクタ番号 */
u8 cylinder = (u8)(regs[V86_REG_ECX] & 0xFF);        /* CL */
u8 sector_len = (u8)((regs[V86_REG_ECX] >> 8) & 0xFF); /* CH */
u8 head_dh = (u8)((regs[V86_REG_EDX] >> 8) & 0xFF);  /* DH */
u8 sector_dl = (u8)(regs[V86_REG_EDX] & 0xFF);       /* DL */
```

この修正により、FreeDOS IPLが正しくFATやルートディレクトリ、および `kernel.sys` のデータを読み出せるようになるはずです。

## 4. 追加のデバッグと問題解決 (2026-05-03 追記)

その後のテストにより、FreeDOSブート中に新たなクラッシュ（#PFによるカーネルパニック）とハングアップが発生する問題に直面し、以下の原因を特定・修正しました。

### ① Timer割り込みの無限再帰によるスタックオーバーフローとIVT破壊
V86タスクにタイマ割り込み（IRQ0 -> INT 08h）を注入するロジック (`v86_inject_timer_irq`) が、ゲスト側の **仮想PICのISR（処理中フラグ）およびIMR（マスクフラグ）を無視して強制的に注入し続けていた** ことが判明しました。
V86エミュレーションは物理CPUより圧倒的に遅いため、ゲストOSがTimerハンドラを抜け出して `IRET` を実行する前に、次の10msタイマ割り込みが発生し、また注入されるという **無限の再帰呼び出し状態** に陥っていました。
これにより、ゲストのスタックポインタ (`SP`) が `0xFFFE` から減少し続け、最終的に `0x005A` 付近まで到達（スタックのラップアラウンド）。これにより **IVT (Interrupt Vector Table, 0x00000付近) を割り込みフレーム (EFLAGS, CS, EIP) で上書き** してしまい、破壊されたIVTから不正なセグメント（`0xFD61`など、BIOS ROM領域）を読み込んで実行しようとした結果、ReadOnly領域への書き込みによる `#PF` でカーネルがパニックしていました。
**【解決策】** `v86_inject_timer_irq` 内で仮想PICの IMR および ISR の bit 0 をチェックし、すでにタイマ割り込みがマスクされている、または処理中である場合は新たな注入を保留するよう修正しました。これにより割り込みの多重発生を防ぎました。

### ② FDIディスクイメージのヘッダ未考慮によるブート失敗
ユーザーから新たに提供された `dos5_1.fdi` イメージを使用してテストしたところ、ブート直後の最初の命令 (`CS:EIP = 1FC0:0000`) で不正なオペコード `0xF1` (ICEBP) に遭遇し、即座にV86モードが終了する事象が発生しました。
調査の結果、`.fdi` 形式のディスクイメージファイルには **先頭に 4096 バイト (0x1000) または 8192 バイト (0x2000) のヘッダ** が存在することが原因でした。従来のRAW形式 (`.img`) と同じようにオフセット 0 から VFS 経由でメモリに読み込み、先頭のデータをそのまま IPL として V86 空間の `0x1FC00` にコピーして実行しようとしていたため、FDIヘッダのデータ（管理情報等）を機械語として誤実行していました。
**【解決策】** `v86_boot_freedos` において、読み込んだイメージファイルのオフセット 0x08 に記録されている FDI ヘッダサイズを解析し、サイズが `0x1000` や `0x2000` の場合はそれを「データ開始オフセット」として扱うよう修正しました。これにより、ディスクエミュレータ（`v86_disk.c`）および IPL のコピー処理が正しいFATブートセクタから行われるようになりました。

## 5. 現在の最新ステータス

上記2つの修正（仮想PICのISRチェックによる割り込み保護、およびFDIヘッダスキップ対応）に加え、以下の追加修正を実施。

### ③ GPトラップ上限をタイムアウトベースに変更 (v86.c)
- 旧: `v86_gp_count > 5000` (固定カウント) → FreeDOSカーネルが起動時に発行するGP/INTが多すぎて即座にタイムアウト
- 新: `tick_count - v86_start_tick > 1000` (10秒タイムアウト)
- INTカウント上限 (10,000,000回) も削除し、タイムアウトに統一

### ④ BDA/メモリスイッチの追加初期化 (v86_mem.c)
以下のBDAフィールドを新規追加:
- `0x0458` (BIOS_FLAG5): 非NESAアーキテクチャ = `0x00`
- `0x0482` (SCSI HD接続): HDDなし = `0x00`
- `0x055D` (SASI/IDE HDD): HDDなし = `0x00`
- `0x03FE` (ブートパーティション): `0x00`
- `0x05AE` (メモリサイズ): 640KB = `0xA0`

TVRAMメモリスイッチのWORDアクセスに修正し、適切なデフォルト値を設定:
- MEMSW1 = `0x48` (25行モード)
- MEMSW2 = `0x01` (10MHzクロック)
- MEMSW3 = `0x04` (31kHz CRT)

### ⑤ INT 18h BIOSファンクションの拡充 (v86_bios.c)
以下のファンクションを新規実装:
- `AH=0Eh` (ファンクションキーライン制御) → NOP
- `AH=14h` (テキストVRAM 1文字書き込み) → TVRAM直接書き込み
- `AH=15h` (テキストVRAM 1文字読み出し) → TVRAM直接読み出し
- `AH=17h` (アトリビュート設定) → TVRAMアトリビュート書き込み
- `AH=1Ah` (行スクロールアップ) → TVRAMスクロール
- `AH=1Bh` (行スクロールダウン) → NOP
- `AH=40h/41h` (グラフィック画面表示/停止) → GDCコマンド
- `AH=42h/43h` (パレット設定/取得) → NOP

現在クリーンビルド済み。デプロイしてNP21/Wで再テストを行う段階。
