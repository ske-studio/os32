# FreeDOS(98) カーネル初期化フローと依存リソース分析

本ドキュメントでは、FreeDOS(98)のカーネル(`kernel.sys`)が起動する際の初期化フローと、その過程でアクセスされるPC-98特有のリソース（BDA、ポート、TVRAM等）についてまとめます。V86モードでの動作におけるハングアップ原因特定の基礎資料となります。

## 1. カーネルエントリと基本初期化 (`main.c`)

ブートローダから制御が移り、`FreeDOSmain()` 関数が実行されます。

1. **BSS領域の初期化**: `memset`によるゼロクリア。
2. **IVTの参照 (UPXチェック)**: `0000:0200` (`INT 80h`のベクタ) を参照し、"CONFIG"文字列があるか確認。
3. **ブートドライブ設定**: BDA等から渡されたブートドライブを初期化。

## 2. 割り込みベクタの乗っ取り (`setup_int_vectors`)

OS32側のV86ハンドラが設定したIVTを、FreeDOSカーネルが自身のハンドラで上書きします。

- `INT 00h` (ゼロ除算), `INT 01h`, `INT 03h`, `INT 06h` (無効オペコード)
- `INT 20h`〜`INT 2Fh` (DOS API関連)
- **`INT 29h` (高速コンソール出力)**:
  - FreeDOSカーネル内部の `int29_handler` に書き換えられます。
  - 以降の `printf` やコンソール出力はすべてこのハンドラ（実体は `int29dc.c` 内の `_int29_main`）を経由します。
- `INT 40h`〜`INT FEh`:
  - 全て `unhandled_int_handler_iosys` に向けられます。
  - OS32がV86側にフックとして設定していた独自のINT（もしあれば）も上書きされます。

## 3. カーネルコア初期化 (`init_kernel`)

カーネルの主要な初期化処理が行われます。ここで多くのPC-98固有リソースにアクセスします。

### 3.1 `init_oem()` と `InitPC98()`
- **BDA `0x0501` (装備フラグ)**: ビット情報を読み出し、搭載メモリサイズを計算。
- **BDA `0x0401` (128KBメモリサイズ)**: 読み出し。
- **セグメント `0x0060`**: `0060:0020` 付近に DOSのバージョン/製品ID情報を書き込みます。

### 3.2 デバイスドライバ初期化 (`InitIO` -> `init_crt`)
コンソールドライバの初期化処理である `init_crt()` (`console.asm`) が実行されます。
**※重要**: `INHERIT_CURSOR_POSITION` マクロは未定義のため、GDCステータスポーリング（ポート `0x60` のビジーウェイト）は実行されません。

- **`INT 18h`**:
  - `AH=0Bh` (CRTモード取得)
  - `AH=0Ah` (CRTモード設定)
  - `AH=0Ch` (テキスト画面表示)
  - `AH=11h` (カーソル表示)
- **BDA `0x0501` (装備フラグ)**: ビット3をチェックし、ノーマル(A000)/ハイレゾ(E000)を判定。
- **TVRAMアクセス**:
  - `0xA000:3FE2`〜`3FF7` を読み出し、メモリスイッチ情報（MEMSW1〜MEMSW6）としてセグメント `0x0060` の `0060:0068`〜`0060:006B`, `0060:008D`〜`0060:008E` に保存します。
  - この値が未初期化（0）の場合、以降のコンソール出力動作に異常をきたす可能性があります。
- **初期化文字列の出力**: `INT 29h` を使用して `ESC [ > 1 l` を出力します。

### 3.3 コンソール出力ハンドラ (`_int29_main` / `int29dc.c`)
上記 `InitIO` 以降の文字列出力で実行される非常に巨大な関数です。
- **BDA参照**: `0x053C` (CRT_STS_FLAG), `0x0482` (SCSIフラグ), `0x0460` (システムタイマ関連)
- セグメント `0x0060` の変数領域を広範囲に読み書きします。
- VRAM (TVRAM, GVRAM) への直接書き込みと、GDCコマンド（ポート `0x60`, `0x62`）の発行を行います。

### 3.4 ディスク初期化 (`dsk_init`)
ディスク（FDD/HDD）の構成を認識します。
- **`printf` 呼び出し**: " - InitDisk" を出力（`INT 29h` 経由）。
- **BDA参照**:
  - `0x0584` (DISK_BOOT)
  - `0x03FE` (BOOTPART_SCRATCHPAD)
  - `0x055D` (SASI/IDE HDD接続情報)
  - `0x0482` (SCSI HDD接続情報)
- **BIOS呼び出しと直接I/O**:
  - `INT 1Bh AH=03h` (ディスク初期化)
  - `INT 1Bh AH=05h` 等 (セクタ読み出し)
  - アセンブリルーチン `fl_sense()`, `fl_readid()` により、`INT 1Bh` の別ファンクション（もしくは直接I/O）が発行される可能性があります。

### 3.5 ファイルシステム初期化とCONFIG.SYS処理 (`FsConfig`, `DoConfig`)
- `AUX`, `CON`, `PRN` デバイスのオープン。
- ディスクから `CONFIG.SYS` を読み込みます（ここでさらに `INT 1Bh` が発生）。

## 4. V86エミュレーションにおけるハング原因の可能性（優先度順）

これまでの調査から、OS32側のV86エミュレータ上でFreeDOS(98)がハングする原因として以下の優先度で仮説が立てられます。

1. **仮説 A: 未初期化BDAおよびセグメント0x0060による `int29dc.c` の無限ループ**
   `setup_int_vectors` 後、最初の `printf` で `int29dc.c` が呼び出されます。このとき、OS32側で初期化していないBDA（`0x053C` 等）や、`init_crt` で TVRAM（`0xA000:3FE2`等）から読み出された不正なメモリスイッチ値（0など）によって、コンソール描画ループが無限ループに陥っているか、異常なメモリアクセスを行っている可能性が最も高いです。

2. **仮説 B: 未実装の `INT 18h` または `INT 1Bh` ファンクション**
   `init_crt` や `dsk_init` で発行されるBIOSコールがOS32の `v86_bios.c` で未実装（単に0や-1を返すだけ）の場合、カーネルのロジックが破綻しビジーウェイト等に陥る可能性があります。

3. **仮説 C: システムタイマ割り込み (`INT 08h`) またはキー入力待ち**
   特定の処理でタイマの更新（BIOSカウンタの増加）や、予期せぬキー入力待ちが発生している可能性があります。

## 今後のデバッグ方針

まずはOS32カーネル（`v86.c`, `v86_bios.c`）に詳細なトレースログ出力（INT発行履歴、I/Oポートアクセス履歴）を組み込み、ハングアップ直前に最後に呼ばれた命令やBIOSファンクションを特定します。同時に、確実性の高い「BDAとTVRAMメモリスイッチの初期化」をV86メモリセットアップ時に行います。
