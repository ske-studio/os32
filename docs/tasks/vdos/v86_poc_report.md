# V86 Mode — Phase 0 完了レポート

## 概要

PC-9800シリーズ (OS32) において V86 (Virtual 8086) モードの動作を実証し、
カーネル本体に統合した。Phase 0 (V86基盤) は完了。

---

## Phase 0-A: FDDブートPoC (単体テスト)

### 目的

OS32カーネルから独立した最小アセンブリプログラム (`tests/v86_fdd_test.asm`) で、
V86モードの全実行パスをFDDブートで証明する。

### 実行結果

```
Ld PM T I G V
V86 PASS
X000084FE
```

- `Ld PM T I G V` — ロード、PM移行、TSS/IDT/ページング/V86コード展開が正常終了
- `V86 PASS` — V86モード遷移 → HLT → #GPトラップ → PM復帰の全パス成功
- `X000084FE` — タイマ割り込みが正常処理されシステムが安定動作

### 直面した技術的課題と解決策

| 課題 | 原因 | 解決策 |
|------|------|--------|
| INT 1Bh FDDリードエラー | AH=76h (リトライなし) 指定 | boot_fat.asm (既存FATローダー) に全面移行 |
| 物理アドレスの計算ミス | ロード先変更時にオフセット未更新 | `[org 0x8000]` でNASMに自動解決させる |
| IDTハンドラの不正アドレス | 同上の計算ミスが波及 | 同上 |
| GDT自己破壊 | boot_fat.asm がロード時にGDT領域を上書き | GDTを安全なアドレスに再配置 |

### 鍵となった設計判断

1. **既存ブートローダー (boot_fat.asm) の活用** — 自作ブートセクタを廃止
2. **V86コードの空間分離** — テストコードを `0x10000` に配置しカーネル領域と分離
3. **リニアアドレスのネイティブ解決** — `[org 0x8000]` で全アドレス計算を自動化

## Phase 0-B: カーネル統合 (v86_test)

### 目的

PoCで実証したロジックをOS32カーネル本体に統合し、
カーネル環境下でV86モードが正常動作することを検証する。

### 実装内容

| ファイル | 内容 |
|----------|------|
| `kernel/v86.c` | #GPハンドラ (CLI/STI/HLT/INT/PUSHF/POPF/IRET/IN/OUT) |
| `kernel/v86.h` | V86コンテキスト構造体、レジスタインデックス定義 |
| `kernel/v86_test.c` | カーネル統合テスト (メモリ設定→V86遷移→復帰) |
| `kernel/v86_entry.asm` | IRET によるV86モード遷移 |
| `kernel/isr_stub.asm` | `.v86_gp` / `.v86_pf` パス追加 |
| `kernel/paging.c` | `paging_pde_set_flags()` / `paging_pde_clear_flags()` |

### 検証結果

NP21/W上でカーネルをビルド・デプロイし、ブートスプラッシュ表示まで正常動作を確認。

```
V86 OK!            ← V86テストコードがTVRAMに直接書き込み (成功)
V86 TEST...OK       ← カーネルからの検証結果表示 (成功)
[ブートスプラッシュ]  ← カーネルが正常に起動継続
```

### 発生した致命的バグと修正

**症状**: V86テストコードがTVRAMに "V86 OK!" を書き込んだ直後にトリプルフォルト。

**原因**: `isr_stub.asm` の `.v86_gp` パスで、`pushad` 直後に DS/ES をカーネル
データセグメント (0x10) に復元していなかった。
V86→Ring0遷移時にCPUが DS/ES/FS/GS を **0にクリア** する仕様
(Intel SDM Vol.3 §20.3.1.2) への対処漏れ。

**修正**:

```nasm
.v86_gp:
    pushad
    ;; ★ 必須: DS/ES復元
    mov     ax, 0x10
    mov     ds, ax
    mov     es, ax
    ;; Cハンドラ呼び出し
    mov     eax, esp
    push    eax
    call    v86_gp_handler
```

> [!CAUTION]
> この修正はFDD PoCでは最初から正しく実装されていたが、
> カーネル統合版の `isr_stub.asm` への反映が漏れていた。
> V86モードを扱う全ての例外ハンドラで同様の処理が必要。

## Phase 0 で確立されたV86お作法

1. **V86モードへの遷移**: Ring 0 スタックに GS/FS/DS/ES/SS/ESP/EFLAGS(VM=1)/CS/EIP を
   積み IRET で遷移する (v86_entry.asm)
2. **ページングの必須化**: V86アドレス空間はページテーブルで制御。
   PDE/PTEともに `PTE_USER` が必要
3. **例外発生時のDS/ES復元**: CPUがセグメントレジスタを0にクリアするため、
   #GP/#PFハンドラの先頭で即座にDS=0x10, ES=0x10を設定
4. **特権命令のエミュレーション**: CLI/STI/PUSHF/POPF/INT/IRET/HLT/IN/OUT を
   #GPハンドラ内で解釈し、仮想IFフラグ等で管理
5. **I/Oビットマップ**: TSS内に8192バイトのビットマップを配置し、
   ポート単位で許可(0)/トラップ(1)を制御
6. **V86終了**: `v86_gp_handler` が戻り値 1 を返すと `isr_stub.asm` が
   V86モードを終了し、`v86_test_exit` → `exec_longjmp` でカーネルに復帰
