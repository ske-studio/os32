## 3. 配備処理の反例と確認方法

対象は [tools/hostdrv_deploy.py](../../../tools/hostdrv_deploy.py)。
2026-09-19 のレビューで、該当関数をソースから抽出し、ファイルは一時ディレクトリへ、
配備定義と保護判定などの依存は試験用に差し替えて反例を確認した。
実配備・ゲストの hsync・本来の全体テストを実行した結果ではない。

| ID | 手順 | 観測結果 | コード上の位置 |
|---|---|---|---|
| M07 | 旧 manifest を置き、a を更新した後 b の copy2 に ENOSPC を注入 | OSError で終了。a は更新済み、旧 manifest が残る | copy2（基点469行）を囲う共通例外処理がなく、sync_failed を通らない |
| M08 | 明示エントリ a／b のうち b のソースを欠損させる | do_sync が True。manifest に a だけが載る | resolve_files_from_entry（335〜369行）と空リストの continue（429〜431行） |
| M09 | 旧 manifest の unlink に EACCES を注入し no-manifest で同期 | do_sync が True。旧 manifest が残る | remove_manifest の戻り値未確認（487〜490行） |

コピー例外は非ゼロ終了になるため、「例外でも配備コマンドが成功する」とは言わない。
M07 の問題は失敗後の旧名札が混在した内容を正しく表さず、後の世代照合を誤らせ得ること。
M08 は H4 の前からある列挙の扱いが、新しい「全件成功」の名札にも伝わる問題。
M09 は H4 の部分配備で旧名札を消すという契約と実装の不一致。

[書く側の既存試験](../../../tools/tests/test_hostdrv_manifest.py) の M2 は保護判定の失敗を注入しており、
copy2 の例外とは別経路。修正時は実モジュールを使う回帰へ上記の反例を追加する。
配備前の必須欠損、2件目のコピー失敗、名札削除不能を独立に検査し、
ファイル内容・名札の存在・終了状態を併せて観測する。
