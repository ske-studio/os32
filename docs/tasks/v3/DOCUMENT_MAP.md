> 調査基点: `76c69ddc7601b36e5fae4897ce8a9274e89ed33a`。

[計画書](PLAN.md) / [移行課題台帳](MIGRATION_AUDIT.md) / [現行索引](../../INDEX.md)。
ここは分類と移行方針の記録であり、現行仕様・進捗を複製して更新する新たな正典にはしない。

## 1. 読み方と優先関係

v3 の新しい判断は計画書の「提示方針／計画案／未決」を出発点にする。
現行動作の確認は実装と現行仕様を照合し、食い違いを台帳へ記す。
過去のタスク票や承認が、新しいリポジトリでの作業許可になるとは扱わない。
コードの挙動と意図した契約が異なるときは、コードに合わせて契約を黙って変えない。

## 4. 過去の作業情報として隔離する資料

| 資料 | 現行リポジトリでの扱い | 将来の v3 作業ツリーでの扱い |

| [HANDOVER_v14](../agents/HANDOVER_v14.md) | 撤回済みの方針として保持 | 作業指示として取り込まない |

| [ROLES](../agents/ROLES.md) とAI向け入口 | 現行系の運用として維持 | モデル名・利用枠・個人環境・個別承認を持ち込まず、新環境用に作成 |
| [POLICY_DEBUG](../../POLICY_DEBUG.md) | 障害の原因と再発防止の根拠 | 現在も必要な制約と回帰試験を抽出。長い時系列を通常の起動資料にしない |

現行系の文書を一括削除したり、リンクを切る形で動かしたりしない。
物理的な archive 移動は既存の [移動手順](../../archive/README.md) に従い、
相互リンクと生成された試験一覧を同時に更新する。今回は分類・入口・状態を整理する。
v3 フォーク時に通常作業ツリーから旧資料を外す処理は、その分岐点で改めて行う。

## 6. 文書整理の終了条件

- 新規計画・台帳・本分類に現行索引から到達できる。
- 既存の履歴とリンクを保持し、今回追加・変更した参照先が実在する。
- 受入記録・未実施・現在の指摘が区別され、文書の状態修正をコード修正と誤認しない。
- 現行系の C89 規約・コード・ビルド条件は変更しない。
- v3 の正式な作業開始時には分岐 SHA を更新し、本分類のスナップショットを再確認する。
