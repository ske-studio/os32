## 高優先度: UI 拡張

### 候補操作の拡充

現在の候補選択は Space (次候補) のみ。以下を追加する:

- [ ] **↑/↓ キーによるリスト送り**
  - `KEY_UP` / `KEY_DOWN` スキャンコードの検出
  - 変換候補表示中に `candidate_idx` を増減
- [ ] **数字キー (1-9) ダイレクト選択**
  - 候補ウィンドウに番号を表示
  - 対応する数字キーで即座に確定
- [ ] **候補ページング**
  - `IME_MAX_RESULTS` (32) を超える候補がある場合のページ送り
  - Tab / Shift+Tab でページ切り替え

### GFX モード対応

現在の TVRAM ベースの UI はテキストモードアプリでのみ動作する。
グラフィックモードアプリ (gfx_demo 等) で FEP を利用するには:

- [ ] **GFX VRAM 退避・復元**
  - グラフィックVRAM 下部 (Y=384〜399, 16ライン) を 4 プレーン分退避
  - 退避先: `mem_alloc` (80B × 16lines × 4planes = 5,120B)
  - FEP 表示終了時に書き戻し
- [ ] **GDC テキスト/グラフィック混在制御**
  - `0x68` ポート (画面モード制御) でテキスト/グラフィック両方の表示を有効化
  - テキスト VRAM の表示 ON/OFF 切り替え関数 (`tvram_set_visible()`)
- [ ] **漢字 ROM ビットマップ直接描画**
  - グラフィックモード時はフレームバッファプレーンへの直描画
  - `kcg_read_kanji()` + 各プレーンへのビットマップ転送

### TVRAM スクロール保護

- [ ] **`tvram_scroll` を 24 行制限に変更**
  - 現在の `console.c` は `TVRAM_ROWS` (25行) をスクロール対象としており、FEP 表示領域 (25行目) を巻き込む
  - FEP ON 時はスクロール範囲を行 0〜23 に制限

## 中優先度: KAPI 公開

現在の IME API はカーネル内部関数のみ。
外部プログラムから IME を制御するための KAPI 公開:

- [x] **`ime_enable` / `ime_disable`** — FEP の有効/無効切り替え (ime_set_mode等で代替完了)
- [x] **`ime_get_mode`** — 現在のモード取得 (OFF/HIRAGANA/KATAKANA)
- [x] **`ime_set_mode`** — モード設定
- [x] `kapi.json` への追加 + `kapi_generated.c` 再生成

用途: VZ エディタ等がプログラム的に FEP を制御するケース。

## 中優先度: 辞書品質向上

- [ ] **IPADIC 以外の頻度データ取り込み**
  - Wiktionary 頻度表、青空文庫コーパス等
  - `fep_to_sqlite.py` のコスト計算ロジックに統合
- [ ] **PRAGMA 最適化**
  - `synchronous=OFF` / `journal_mode=MEMORY` で IME 確定時のラグ削減
  - トレードオフ: クラッシュ時の学習データ損失リスク
- [ ] **辞書バリアント動的切り替え**
  - シェルコマンド `ime dict s|m|l` で辞書を切り替え
  - `ime_dict_open()` の再呼び出しで実現可能
- [ ] **学習辞書の永続化検証**
  - NP21/W 再起動後も `dict_user` のデータが保持されることの継続テスト

## 低優先度: 連文節変換 (将来構想)

現在は単文節の最長一致法。将来的に連文節変換を実装する場合の構想:

- [ ] **← → キーによる変換範囲変更**
  - かなバッファ内の「文節境界」をユーザーが手動調整
- [ ] **Viterbi / bi-gram ベースの最適分割**
  - コスト最小パスで自動文節分割
  - 2-gram 連接コストテーブルが必要 (辞書サイズ大幅増加)

> 実装コストが非常に高く、メモリ制約 (MEMSYS5 100KB) との兼ね合いもあるため、
> 当面は単文節変換 + 学習辞書で十分な品質を目指す。
