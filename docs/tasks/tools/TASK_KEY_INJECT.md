# TASK_KEY_INJECT — キー注入で任意のバイトを送れるようにする

> 発行: PM (Claude Code `claude-opus-5`、2026-09-17) / 状態: **計画 (2026-09-17)**

基点: `feat/gui` = `5459b20`。
発見: [`../gui/TASK_EDIT_GUI.md`](../gui/TASK_EDIT_GUI.md) §7-2 (受入 E2〜E7 がこれで止まった)。
経緯: [`../../POLICY_DEBUG.md`](../../POLICY_DEBUG.md) §4-43。

**直す先は NP21/W (`/home/hight/np21w-src`) と `tools/gui_gate.py` の両方。**
OS32 本体は変えない。**検証の側の穴**であって製品の穴ではない。

## 0. 症状

`/api/key` に `text=ABC` を送ると、ゲストには **`abc`** が届く。
CUI のシェルでも GUI でも同じなので、**アプリの問題ではなく注入の側**。

そのため大文字や修飾キーが要る経路 (**日本語入力、クリップボード、印刷**) を
**自動で確かめられない**。2026-09-17 のエディタの受入 E2〜E7 がこれで止まった。

## 1. 原因 (確認済み)

`np21w-src/src/win9x/aidebug/aidebug_keys.cpp:155` の
`aidebug_key_ascii_to_nkey()`:

```c
int aidebug_key_ascii_to_nkey(char ch, int *nkey, int *needshift)
{
    /* letters */
    if (ch >= 'a' && ch <= 'z') {
        ch = (char)(ch - 'a' + 'A');      /* ← 小文字を大文字に畳む */
    }
    *needshift = 0;                        /* ← そのあと 0 に固定 */

    switch (ch) {
    case 'A': *nkey = 0x1d; return 1;      /* 'a' も 'A' もここへ来る */
    ...
```

**`'A'` と `'a'` が同じ経路に入り、`needshift` が 0 のまま**なので、
英字は**常に小文字**として送られる。

**仕組み自体は揃っている。** 記号は正しく立てている
(`case '!': *nkey = 0x01; *needshift = 1;`)。**英字だけが漏れている。**

`_` が通るのは、別の記号として明示的に扱われているため。

## 2. 直し方

### 2-1. まず英大文字 (これだけで E2〜E7 が動く)

畳む前に大文字かどうかを見て `*needshift = 1` にする。**数行で済む。**

**確かめること**: `text=ABC` で `ABC` が届く。`text=abc` は `abc` のまま (退行させない)。

### 2-2. 任意のバイトを送れるようにする (ユーザー提案 2026-09-17)

**英大文字だけ直しても、送れない文字は残る。** 制御文字、`\`、そして
`text=` に載せられない値。**逃げ道を作る。**

案 (どれを採るかは実装者が決めて票に書き戻す):

| 案 | 形 | 長所 | 短所 |
|---|---|---|---|
| **A: 逃がし記法** | `text=A\x1bB` / `\\` で `\` 自身 | 読める。既存の `text=` と混ぜられる | `\` を含む文字列を送るとき気を遣う |
| **B: base64** | `text64=QUJD` | **曖昧さが無い**。何でも送れる | 読めない。目で確かめられない |
| **C: 両方** | `text=` は A、`text64=` を足す | 普段は読める形、困ったら B | 口が 2 つ |

**PM の推しは C だったが、実装者が退けた。その判断が正しい** (2026-09-17、書き戻し)。

### 決まった案 — **D: 展開は台本側に置く**

**C も A も `aidebug_api.cpp` を触らずには作れず、しかも A は既存の振る舞いを変える。**

| 案 | なぜ駄目だったか |
|---|---|
| A (逃がし記法を `text=` に) | **今 `text=\` は PC-98 の円記号キー (0x0d) を送る。** `\` を逃がし記号にすると**それが黙って別物になる** — 票が自ら禁じた「既存の振る舞いを変えない」に正面から反する |
| B (`text64=`) | 新しいフォーム項目を `handle_key()` で読む = **確実に `aidebug_api.cpp`** (他人が変更中) |
| C (両方) | A と B の両方の問題を持つ |

**採った形**:

- **展開は `tools/gui_gate.py` の `expand_escapes()` に置く。** `/api/key` の `text=` の意味は
  **1 ビットも変えない**。制御文字は既存の `seq=` の和音 (`CTRL+A`〜`CTRL+Z` / `ESC` /
  `TAB` / `BS` / `DEL` / `RETURN`) に落とす。
- `key(..., escapes=False)` が**既定**。受入 K6 (既存の台本が動く) を**構造的に**保証する。
- エミュレータ側にも `aidebug_keys.cpp` だけで閉じる逃げ口を 1 つ足した:
  `aidebug_key_name_to_nkey()` が **`NKEY:1d` (生スキャンコードの 16 進)** を解す。
  `s_named[]` に `NKEY:` で始まる名前は無いので**純粋な追加**で、`seq=SHIFT+NKEY:1d` と組める。

### 送れないもの (この案の上限)

- **0x80 以上は生キー注入では原理的に送れない** (かな・漢字は FEP 経由)。
- `0x00` と `0x1C`〜`0x1F` は対応キーが不確かなので、`gui_gate.py` は**黙って捨てず
  `ValueError`** にする。

### 併せて分かった罠 (実装者の報告)

1. **`seq=A` は大文字にならない。** 名前の解釈は shift を捨てて nkey だけ返すため。
   名前は「文字」ではなく「キー」を指すという解釈なので**直していない**。大文字が要るなら `seq=SHIFT+A`。
2. **ゲスト側で CAPS LOCK が ON だと SHIFT+英字は逆に小文字になる。**
   大文字が出なかったら**まず CAPS を疑う**。
3. `\n` を `RETURN` に落としている。**0x0A と 0x0D を区別したい受け手には合わない。**

**どの案でも守ること**: **既存の `text=` の振る舞いを変えない。**
`tools/gui_gate.py` と `tools/emu_agent/` の既存の台本が動かなくなると、
**今日作った試験ランナーごと止まる。**

### 2-3. `tools/gui_gate.py` 側

`key(text=...)` は 4 文字ずつ送る (raw リングが 32 エントリしかないため、
[`POLICY_DEBUG.md`](../../POLICY_DEBUG.md) §4 に経緯)。**この分割は残す。**
逃がし記法を入れるなら**分割が記法の途中で切れないこと**。

## 3. FEP の起動は SHIFT+SPACE (訂正)

PM は当初「FEP の起動に大文字が要る」と書いたが**誤り** (ユーザー指摘 2026-09-17)。
FEP は **SHIFT+SPACE** で起動する。`seq=SHIFT+SPACE` は既にあり、
[`POLICY_DEBUG.md`](../../POLICY_DEBUG.md) §4-23 に
**`--data-urlencode` で送る** (`-d` だと `+` が空白になる) という注意もある。

**つまり FEP の起動自体は今でもできる。** 止まっていたのは
**確定した日本語を打ち込む経路**と、大文字を含む操作。
