# 対戦スゴロクRPG — 画面デザイン仕様

*策定: 2026-08-18*

`docs/tasks/game/GAME_PORT_PLAN.md` の Phase 0/1 で作った暫定UIを、
ドカポン3・2・1 (SFC) のフィールド表現を参考に作り直すための仕様。

モックは `tools/uimock*.py` が生成する。すべて **640×400 / PC-98 16色 /
実フォント**でレンダリングしているので、出力画像は実機の見え方と一致する。
出力先は `docs/tasks/game/ui/`。

---

## 1. 決まったこと

### 1.1 パレット — 退色レトロ地図風

**カーネル既定のパレットは各成分が 0/7/15 の原色しか使わないため派手になる。**
PC-98 のパレットは書き換えられるので (`KAPI: gfx_set_palette(idx, r, g, b)`、
各成分 0-15)、ゲーム起動時に独自の16色を流し込む。

定義は `tools/uimock_palette.py`。`c_source()` が C の配列を吐く。

マップ背景は**海＋陸3段の4色**だけで成立させ、地形の描き分けは色数ではなく
タイルの模様で行う。建物とキャラだけ彩度のある色を少数使って浮かせる。

| idx | 用途 | RGB(4bit) |
|-----|------|-----------|
| 1 | 海 (深) | 2, 4, 5 |
| 3 | 陸 (低) モス暗 | 4, 7, 3 |
| 4 | 陸 (中) モス ← 面積最大 | 7, 10, 4 |
| 5 | 陸 (高) 明モス | 10, 13, 6 |

### 1.2 フィールドの表現 — 矢印方式

**マスはブロック(台)ではない。地形は連続していて、すごろくの道は
地面に置かれた矢印 (▷ ▽ ◁ △) の列で示される。矢印1つ = 1マス。**

> 設計中に2回誤った解釈をした。1回目は「地図＝連続地形」と考えてマスの境界を
> 消しすぎ、2回目は参考画像を見て「マス＝立体ブロック」と解釈した。
> どちらも違い、正解は「連続地形 + 矢印マーカー」。

- グリッド1マス = 48×48px。盤面 400×304 に 8×6 セル入る
- 道になっているセルにだけ矢印が出るので、視界に入るマスは 10〜20
- 施設 (村・店・神社・城・洞窟) は地形の上に建物として建つ
- 村には名前の看板を添える
- 解像度が原典と異なるため厳密な一致は狙わない

### 1.3 キャラクタ

- サイズ **22×32** (道の上に立つ。マス間隔 48px の 2/3 強)
- **描画順のルール**:
  1. 奥 (グリッド y が小さい) から手前 (y が大きい) へ描く
  2. 同じマスに複数いる場合、**手番プレイヤーを最後に描いて最前面に出す**
- 手番プレイヤーの頭上に ▼ マーカー (黒縁付き。地形に紛れないように)

### 1.4 画面構成

ドカポン321 は「上部ステータス帯 + 左コマンドメニュー + 右上の週/曜日」だが、
**本作は従来の構成を維持する**。

```
+------------------------------+----------------+
|                              |                |
|  盤面 400x304                |  情報パネル    |
|  グリッド48px / 矢印方式     |  240x304       |
|                              |  4人の順位     |
+------------------------------+----------------+
|  下段窓 640x96  メッセージ / コマンド / 分岐選択  |
+---------------------------------------------------+
```

### 1.5 下段UI — microUI をやめて固定パネル方式 (2026-08-18)

microUI のフローティングウィンドウは、差分描画と組み合わせると
「ウィンドウが消えた後の残像」「バトル中のウィンドウ消失」の温床になった。
マウスを使わないゲームなのでウィンドウ機構自体が過剰と判断し、
**`view_panel.c` の固定パネル (0,320,640,80) + 行テキスト**に全面移行した。

- 操作は全てキー案内 ("1: Roll Dice   W: Save" のような行) で表示
- `panel_begin()` → `panel_line()`/`panel_line_hi()` → `panel_end()` を毎フレーム。
  行の内容が前フレームと同じなら描画も VRAM 転送も起きない
- バトルのコマンド表示も同じパネルに出す (`view_battle_panel()`)
- microUI は game からリンクごと外れた (バイナリ -21KB)。
  他アプリで使う場合の注意は GEMINI.md の Known Gotchas
  (`mui_pump_input` がキーを食う件) を参照

## 2. 未決 / 課題

1. **矢印が地面に埋もれる。** 参考画像では矢印が連続して帯のように読める。
   矢印の間隔を詰めるか、下に薄い道の帯を敷くか。
2. **キャラクタと地形の質感**が、プログラムで矩形を組む現在のやり方では
   参考画像に届かない。ドット絵を実素材 (`assets/` のタイルセット) として
   起こし、`libos32tilemap` の 4bpp packed へ変換するツールを作るか、
   プログラム描画で妥協するかの判断が必要。
3. **海岸線が階段状。** 方向別の海岸タイル (8方向) が要る。
4. **山地がマスをまたいで連ならない。** 現構造は1マス完結なので山脈や湖を
   表現できない。マスをまたぐ地物を許すかは設計判断。
5. **タイルサイズ。** `libos32tilemap` は `TILE_W/H = 16` 固定。
   8×8 にするなら定数変更が要る。

## 3. モック生成スクリプト

| スクリプト | 出力 | 内容 |
|-----------|------|------|
| `uimock.py` | — | レンダラ本体。描画APIは `libos32gfx` の名前に寄せてある |
| `uimock_palette.py` | — | 退色パレット定義。`c_source()` で C 配列を出力 |
| `uimock_current.py` | `current.png` | 現状UIの再現 (レンダラの受け入れテスト) |
| `uimock_hud.py` | `hud_a/b/c.png` | HUD 3案 (初期検討) |
| `uimock_world.py` | `worldmap.png` ほか | ワールドマップ俯瞰図 |
| `uimock_map.py` | `map_char_*.png` | 8×8タイル案 + キャラサイズ比較 |
| `uimock_map2.py` | `map_retro.png` | 退色パレット適用 |
| `uimock_block.py` | `block_*.png` | ブロック案 (不採用) |
| `uimock_field.py` | `field_arrow.png` | **矢印方式 (採用)** |

`uimock_field.py` は `assets/board.db` の実データを読むので、
盤面を変更すればモックにも反映される。
