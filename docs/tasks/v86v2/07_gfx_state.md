# 07. グラフィック状態の引き渡し (Phase 3-5)

> 作成: 2026-08-09
> 前提: [06_pic_plan.md](06_pic_plan.md) まで完了。Ys のタイトル画面が描画された
> 目的: **画面の乱れを直す** — 絵は合っているのに見え方だけが違う

---

## 1. どこまで来たか

`v86 -b /host/Ys.D88` で **Ys I のタイトル画面が実際に描画された**。
ディスクも割り込みも詰まらず、30 秒のセッション上限まで走り切る。

素の NP21/W で同じイメージを起動して GVRAM を比べると:

| プレーン | 素の NP21/W | OS32 の V86 |
|---|---|---|
| 0 (青) `A8000` | y100:32 y300:31 y380:17 | **同じ** |
| 1 (赤) `B0000` | y100:46 y300:44 y380:32 | **同じ** |
| 2 (緑) `B8000` | y100:40 y300:35 y380:26 | **同じ** |

(数字は各行 64 バイト中の非ゼロ数)

**ゲストが描いた絵はバイト単位で一致している。** 壊れているのは
描画結果ではなく**表示のされ方**だけ。

| | 素の NP21/W | OS32 の V86 |
|---|---|---|
| 見え方 | 640x400 に 1 枚 | 縦半分に潰れた絵が上下に 2 枚 + 右端に断片 |

> プレーン 3 (`E0000`, 輝度) が空なのは**正常**。
> PC-9800 Bible 2-7 に「8色モードではプレーン0〜2の3枚を使用します。
> **プレーン3は存在しません**」とある。Ys は 8 色モードのディザ絵。
> 素の NP21/W 側の `E0000` に値があるのは、そこが 16 色モード用の
> プレーンとして使われていないときの残骸。

---

## 2. 原因 — ゲストはグラフィックを設定しない

観測モード ([§4](#4-観測モード--素通しポートを覗く)) でゲストの
グラフィック I/O を全部記録した結果、**セッション全体でこの 4 回だけ**だった。

```
OUT 0062 = 4B   at 0060:05F0     テキスト GDC
OUT 0062 = 0F   at 0060:05F5     テキスト GDC
OUT 00A2 = 0D   at 0060:0666     グラフィック表示開始
OUT 00A2 = 0D   at 0160:024D     同上
```

**解像度 (`68h`) もカラーモード (`6Ah`) もページ (`A4h`/`A6h`) も
GDC パラメータ (`A0h`) も CRTC も GRCG も EGC も一切触っていない。**

つまりゲストは **BIOS が IPL 直後に残した状態を丸ごと前提にしている**。
1987 年のゲームとしては当然の作りで、BIOS の設定を信じて必要な所だけ
書き換える。

ところが OS32 は `gfx/gfx_core.c` の `gfx_init()` で:

```c
_out(MODE_FF2_PORT, MFF2_16COLOR);      /* 6Ah = 16色 */
_out(GDC_GFX_CMD,   GDC_GFX_400LINE);   /* A2h = CSRFORM */
_out(GDC_GFX_PARAM, 0x00);              /* A0h */
_out(MODE_FF1_PORT, MFF1_HIRES);        /* 68h = 400ライン */
_out(GDC_CMD_START, ...);
_out(GDC_DISP_PAGE,   0x00);            /* A4h = 表示ページ0 */
_out(GDC_ACCESS_PAGE, 0x01);            /* A6h = 描画ページ1 */
```

を設定したままにしている。**この差がそのまま画面の乱れになる。**

> これは「ディスクの物理ヘッド」と同じ形の間違い。
> **ゲストが設定しないものは、こちらが実機と同じ初期値を用意しなければ
> ならない。** 何もしなければ OS32 の都合がそのまま漏れる。

## 3. 試したこと (どちらも不十分)

| 変更 | 結果 |
|---|---|
| `A4h=0` / `A6h=0` / 表示停止 にしてから渡す | 変化なし |
| 上に加えて `68h=09h` (200ライン) | **悪化** — 飛び越し表示になった |

単独のポートを勘で戻しても当たらない。**BIOS 直後の状態一式**を
復元する必要がある。

### 次にやること

1. **素の NP21/W 側で「IPL 直後のグラフィック状態」を採る。**
   ゲストのポートは書き込み専用が多く読み戻せないので、
   エミュレータ内部の状態 (`gdcs` / `gdc` 構造体) を
   `emu_status` に出すのが確実。ai-debug fork なので足せる。
   採るべきもの:
   - モード F/F1 (`68h`) の現在値 = 解像度
   - モード F/F2 (`6Ah`) の現在値 = 8色/16色
   - GDC の SYNC パラメータ (行数・ピッチ)
   - 表示/描画ページ (`A4h`/`A6h`)
2. その値を `gfx_state_for_guest()` に落とす
3. セッション終了時は `gfx_state_for_os32()` で OS32 の設定に戻す
   (VRAM は消さない — ゲストの絵を残すため)

**推測で 1 ポートずつ試さないこと。** §3 の 2 回でそれは無駄だと分かった。

## 4. 観測モード — 素通しポートを覗く

`kernel/v86_io.c` の `v86_io_observe`。

素通しにしたポートは `#GP` を起こさないので `v86_iolog` に何も残らない。
「ゲストがグラフィックをどう設定したか」を知りたいとき、この盲点が
そのまま行き止まりになっていた。

観測モードでは対象ポートを I/O 許可ビットマップから落とし、
ハンドラ側で **ログを取ってから実ポートへ中継する**。
動作は素通しと同じまま、値と発行元 CS:IP が全部見える。

```bash
# 有効化 (再ビルド不要)
emu_write_mem addr=v86_io_observe hex=01000000
v86 -b /host/Ys.D88
emu_read_mem addr=v86_iolog len=1024
```

対象は GDC / モード F/F / CRTC / GRCG / EGC。
常時有効にすると `#GP` が増えて重いので既定は 0。

> **この 1 手で原因が確定した。** カウンタでもログでも見えなかったのは、
> 見たいものが「トラップされない側」にあったから。
> 同じ盲点は他にもある (FM 音源のポートなど)。
