## 動かしてみる

```
v86 -t              V86 セルフテスト (モード遷移 / I/O / IRQ 反射)
v86 -d <image>      INT 1Bh READ DATA をディスクの直読みと突き合わせる
v86 -b <image>      イメージの IPL を 1FC0:0000 に読んで起動する
```

### いまどこまで動くか

**Ys I のタイトル画面が、素の NP21/W とピクセル単位で一致した。**
`v86 -b /host/Ys.D88` で IPL が実行され、`INT 1Bh` が全部成功し、
仮想 PIC 経由で割り込みが回り、30 秒のセッション上限まで走り切る。
セッション終了後は OS32 の描画環境が元通りに戻る (`blit_test` 全項目 PASS)。

640x400 の全画素で差分ゼロ。ディスク・描画・表示のどれにも差が無い。
→ [07_gfx_state.md](07_gfx_state.md)

残っているのは音 (FM)・キー入力・PIT・本編プレイの到達確認。

## 要点だけ

### 方式

**V86 モニタ + 積極パススルー、IOPL=3。**
オーバーヘッドは実測ベースで 6〜13%。ソフトウェアエミュレーションは
必要 3.96 MIPS に対し供給 0.1 MIPS 程度で 30〜100 倍足りず棄却した。

### なぜ成立するか (実測で分かった 3 つの性質)

1. **`INT n` が 0/s** — ゲストは BIOS を INT 経由で呼ばずハードを直接叩く。
   だから IOPL=3 が丸ごと効く
2. **描画が I/O を使わない** — GVRAM へ CPU 直接書き込み。VRAM を直マップすれば
   描画のトラップコストはゼロ
3. **I/O の 7〜8 割が FM 音源の BUSY ポーリング** — I/O 許可ビットマップで
   素通しにすればここもゼロ

### 前回が解けなかった問題の答え

**「FM 音源は検出できるのに曲が鳴らない」**
→ Ys が差し替えている割り込みは **IRQ12 (INT 14h) ただ 1 本**で、演奏は
それだけに依存している。前回の実装は IRQ0/1/2 しか注入しておらず、
ゲストが使う唯一の IRQ を落としていた。
（IVT の直接読み出し + ブレークポイント + 逆アセンブルで確定）

**「NP21/W が PTE の U/S ビットを無視する」**
→ **誤診**。エミュレータの実装は正しい。OS32 自身がトリプルフォルトの
回避策としてカーネル帯に `PTE_USER` を付けていたのが原因だった。
この誤診がカーネル 0x110000 スライドと A20 リバート 4 連発に繋がっていた。

### 今回こちらが一度間違えたこと

**「IOPL=3 なら `INT n` も素通しになる」** — これは誤り。
V86 の `INT n` は IOPL に関係なくプロテクトモードの IDT を引くので、
ゲート DPL=0 / ゲスト CPL=3 の組み合わせで必ず `#GP` になる。
この前提でトランポリン方式を実装してしまい、実機で動かして気づいて作り直した。
結果的には直接デコードの方が簡単だったので実害は無い。
→ [04 §4-7](04_implementation_status.md)

**「D88 のセクタ長はイメージごとに 1 つ」** — これも誤り。
`Ys.D88` は track0 が 256B×16、以降が 1024B×5 で**トラックごとに違う**。
ゲストが `CH` で指定してくる N コードをそのまま信じるのが正しい。
→ [04 §4-12](04_implementation_status.md)

**「Ys が読めないのはコピープロテクトのせい」** — 誤り。
`Ys.D88` は 155 トラック**全部**でセクタ ID が物理位置とずれている。
特定セクタの細工ではなくディスク全体の書式。物理位置は SEEK の CL と DH で
決まり、READ の C/H/R/N は ID 照合にしか使わない。
→ [04 §4-13](04_implementation_status.md) / [05 §3.5](05_disk_bios_plan.md)

**「物理ヘッドは SEEK の DH で決まる」/「AL bit2 で決まる」** — どちらも誤り。
正解は **`DH XOR (AL>>2)`** で、NP21/W の `src/bios/bios1b.c:335` に
そのまま書いてある。セクタ ID 照合に使う `H` は `DH` そのままで、
**トラック選択のヘッドと ID の H は別物**。
実測ログからモデルを起こそうとして 2 回外し、
**リファレンス実装を読んだら 1 行だった**。
→ [05 §3.5.7](05_disk_bios_plan.md)

**「ゲストは必要な設定を自分でする」** — しない。実測で Ys がグラフィックに
出した I/O はセッション全体で 4 回だけ (テキスト GDC 2 回 + 表示開始 2 回)。
解像度もカラーモードもページもパレットも触らず、BIOS が残した状態を丸ごと前提にする。
**ゲストが設定しないものは、こちらが実機と同じ初期値を用意する義務がある。**
→ [07_gfx_state.md](07_gfx_state.md)

**「症状を見て 1 ポートずつ試せば当たる」** — 当たらない。2 回外した。
モード F/F もページもパレットも**書き込み専用で読み戻せない**ので、
ゲストの中からは原理的に答えが出ない。エミュレータ側に `emu_gdc` を足して
状態をそのまま出したら、素の NP21/W との差は 4 項目 + パレットだけだった。
**読めないレジスタは、読める場所から見る。**
→ [07 §3](07_gfx_state.md)

**「タイムアウトがあれば暴走しても戻れる」** — IOPL=3 ではゲストの `CLI` が
実 IF を落とすので、タイマ由来の仕組みは全部効かない。
ウォッチドッグは `#GP` 回数で持つこと。
→ [04 §4-10](04_implementation_status.md)

## 調査の作法

このブランチでは以下を守っている。前回の失敗の裏返し。

- **推測より実測**。「原因を特定した」と書く前に MCP の実測ログを添える
- **リファレンス実装を先に読む**。前回は NP21/W のソースを読むのが遅れ、
  1 週間分の実装 (方法C) が翌日に全撤回された
- **ツールを書いたらその場で使う**。前回は BDA 差分ツール等を書いたのに
  一度も使わずに終わっている
- **新しい asm 経路は書いた直後に 1 命令ずつ検証する**
- カーネルに置くものを絞る。前回は 12,300 行がカーネルに積み上がり
  「ローカル変数すら信頼できない状況」になった

### エミュレータ側に追加した機能

再挑戦にあたって NP21/W ai-debug fork に足したもの。

- **致命的フォルトの捕捉** — トリプルフォルトでモーダルを出さず、
  フォルト地点で凍結してレジスタ・メモリを読めるようにした。
  `emu_fault` / `emu_status` の `fault_generation`
- **ゲスト命令/IO プロファイラ** — V86 コストモデル用。命令クラス別カウンタと
  ポート別 I/O カウンタ、ゲスト命令実行レート。
  `emu_prof_start` / `emu_prof_stop` / `emu_prof`
- **画面状態の露出** — `emu_status` の `scrn_xmax/ymax` `text_disp` `grph_disp`
- **GDC / 画面モードの露出** — `emu_gdc`。モード F/F (`68h`/`6Ah`)、表示/描画ページ、
  デジタルパレット、GRCG、CRTC、uPD7220 のパラメータ RAM (SYNC/CSRFORM/SCROLL/PITCH)。
  **どれもゲストからは読めない**ので、モニタが渡した状態を検証する唯一の手段
