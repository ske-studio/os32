## 決裁 (ユーザー、2026-09-22)

- LAN は v3 の順序 (動的読み込みが先) を待たず、PCI 列挙 → 82557 を静的で入れる (足りなければ SHM を 16KB 削る)。
- 実機のホストは **Ubuntu ノート** (スイッチ直結)。橋は AF_PACKET。この Windows/WSL 機は手で操作する場面だけ。
- シリアルの保険 (番犬) は往復を重ねて直す (Codex 4 往復で打ち止め、最後は設計変更で閉じた)。

## 2026-09-23 の追記 — 結線の土台の設計票

- [`../v3/TASK_HAL_WIRING.md`](../v3/TASK_HAL_WIRING.md) を v4 まで起こした (割り込みの動的登録 / 8237 共通部 / DMA プール / PCI 結線表 / µs 時計)。
  Codex の設計レビューは **3 往復とも Request changes** (v1: 14 件、v2: 9 件、v3: 7 件。件数は減り、v4 で全部反映済み)。
  その後ユーザー許可で往復 4〜7 を実施 (v5 で IRQ0 の汎用 tick 回収を取り下げ、v6/v7 で共有 IRQ の境界を詰めた)。
  **往復 7 (最終) は Request changes だが、残りは「実装前に決める設計判断 2 点」(登録拒否 = 利用不可、動的 IRQ の全登録者に定期回収) と
  「実装レビューで拾う 1 点」(NE2000 の IMR shadow 同期) で、PM が決めて v8 に固定した。実装着手はユーザー判断**。
  ユーザーは v8 を了承し、実装 A (1-1 + 1-5) / B (1-2 + 1-3 + 1-4) を Opus 5 コーダー 2 本で並行開始、設計レビューをさらに 3 往復許可。
  **往復 8〜10 (v9〜v11) で終了**: 往復 10 の残 blocker は R10-1 (CR0.WP = 0 なので出力引数の KAPI が共有ライブラリの .text に書けてしまう) の 1 件で、
  PM が「新設の出力 KAPI は `ring3_user_range_writable` を通し、通らなければ kill」と決めて v11 に固定。以後は実装レビュー。
  **既存の出力 KAPI にも同じ穴がある** (Codex 往復 10) — 別票の残件。
- 決裁待ち 2 点: (1) DMA プールを SQLite 帯の予約域 **0x2E8000〜0x2F7FFF** に固定 (SHM・GUI・SDK・アプリ無変更、SQLite の余地 120KB → 44KB)、
  (2) **PIT の分周が 1.9968MHz 決め打ちの既存バグ** (実機 Ra266 は 2.4576MHz なので tick = 8.125ms、待ち・番犬・校正が全部 23% 速い) を票 1-0 として先に単独で着地。
- **1-0 (PIT のクロック修正) は着地済み** (7269639、Opus 5 コーダー + `make check`)。NP21/W では `kselftest_fail` = 0、tick 99.3Hz で不変。
  **実機の確認が残件**: FD を書き直し → 起動画面に `PIT 2.4576M` → `uptime` を 120 秒あけて 2 回 (直る前は 148 秒進む)。POLICY_DEBUG §4-54。
- 票の外で見つけた不整合: `tools/memmap_audit_live.py` の GUI 基点 `+0x30000` (正典は `MEM_SHM_GUI_OFFSET` = 0x28000)。別の小票で直す。

## 次の実機の回でやること (順に)

1. FD (最新ビルド) で起動、9600 で `ver` → `--fast 115200` (ack の往復と、失敗時の 9600 復帰)。
2. `lspci` と `pcidump 0 <dev> 0` (82557 = 8086:1229、C バスブリッヂ、PCMC) を記録 → TASK_LAN_82557 §5-2 の R1〜R4。`[pci] mech#1 absent` なら 2 値判定を 1 値に緩める。
3. その値で L-B (82557 最小ドライバ) を書く。

## 罠 (今日踏んだもの)

- **エミュレータが模擬しない量**: FDC のシーク時間、DMA の 1MB 制限、FRY、シリアルの速度、CPU 校正の丸め (NP21/W でも 1 周 < 1 tick)。POLICY_DEBUG §4-49〜§4-53。
- **「画面に出ている」は見た目で確かめる** (`/api/screenshot`)。tvram の文字は属性を見ない。
- コーダーの worktree が別系統の基点 (origin/main) で切られることがある — 着手前に `git log -1` の確認を必ず指示に入れる (2 回起きた)。
- セッション切断でバックグラウンドのコーダーが止まる — worktree の未コミット差分は残るので、新しいコーダーに「仕上げ」を頼むほうが速い (transcript の再開より軽い)。
- `make check` 中に票を編集すると `check_tree_unchanged` が落ちる。
