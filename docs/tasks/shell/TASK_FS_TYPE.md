## 1. 共通する誤りの形

`hsync` の H1 で HostDrv の列挙が打ち切りを成功として返していたのを直した (`d574704`) ところ、
**戻り値のエラーを「ディレクトリではない」と読み替えている箇所**が次々に露出した。
往復ごとに 1 箇所ずつ見つかり、修正するたび次の受け手が出た。

| 記号 | 箇所 | 状態 |
|---|---|---|
| B5 | `fs_is_dir()` が `sys_ls` の成功を型判定に使う → `cp -r` が宛先の階層を取り違えて上書き | **修正済** `229ee68` |
| B6 | `vfs_path_kind()` が stat の失敗を「stat 未対応」とみなしてプローブへ落ち、`get_file_size` の成功で FILE と判定 | **修正済** `229ee68` |
| B7 | `vfs_open_internal` が DIR に一致したときだけ拒否し、種別が確定しない負値で open を通す | **修正済** `4a95242` |
| **B8** | **下記。H1 以前からある欠陥なので本票へ** | **未着手** |

共通の規則として置くべきもの: **「読めなかった」と「その型ではない」を混同しない**。
真偽値で型を返す関数は「不明」を運べないので、判定の入口では 3 値以上を使う。

## 2. B8 — I/O 失敗が「不存在」に畳まれ、ディレクトリを open できる

**反例** (Codex 往復 5、PM 確認済み): ext2 上に実在する `/etc` に対し、
パス解決中の親ディレクトリ読み出しが一度 I/O 失敗すると `vfs_open("/etc", O_RDONLY)` が FD を返す。
`cat /etc` がディレクトリの生データを読む。`O_RDWR | O_TRUNC` は `write_file` まで到達する。
`vfs_open_sqlite` も同じ経路。

**根拠**:

- `fs/ext2_dir.c:553` — `ext2_find_entry` の**あらゆるエラーを `EXT2_ERR_NOTFOUND` に畳む**。
- `fs/ext2_vfs.c:261` — `ext2_resolve_path` の失敗を一律 `VFS_ERR_NOTFOUND` に畳む。
- `fs/vfs_fd.c:98` — `NOTFOUND` は `O_CREAT` の経路のために通す必要がある (B7 の修正で意図的に残した)。
- `fs/ext2_file.c:305` — `ext2_get_size_ino` は**型を見ない**ので、ディレクトリの inode サイズを返す。

**H1 以前からある欠陥**である。B7 の前は `kind != VFS_KIND_DIR` で続行していたので、
`NOTFOUND` に畳まれた時点で同じく open へ進んでいた。PM がコードで確認した。

**直す方向** (設計判断が要るので実装前に確定させること):

1. `ext2_find_entry` の I/O エラーを `NOTFOUND` に畳まず区別して返す。
   **`ext2_resolve_path` の呼び出し元が多い**ので、影響範囲の調査が先。
2. `ext2_get_size_ino` (および各 FS の `get_file_size`) がディレクトリを拒否する。
   `hdrv_get_file_size` も同様 (`fs/hostdrvfs.c:600`)。
3. 1 と 2 のどちらを正とするか。2 だけでも B8 の反例は塞がるが、
   「I/O 失敗を不存在と報告する」こと自体は残り、`O_CREAT` が**実在するファイルを消して作り直す**
   経路に化ける可能性がある。**1 を本筋とし 2 を併せて入れるのが妥当と考える** (PM 案)。

## 3. 併せて残っている小さいもの

- **`fs_is_dir` は「不明」を運べない**。stat と列挙の**両方**が失敗すると偽を返し、
  `cp -r` が誤った枝へ進む。H1 以前からの欠陥。解消には `cp`/`mv` が
  `fs_path_kind()` の負値を見て断る必要があり、呼び出し元の変更になる
  (`userland/shell/cmd_file.c` の 5 箇所)。
- **NP21/W の `hostdrvNT_getHostPath`** (`/home/hight/np21w-src/src/generic/hostdrvnt.c:368-390`) の
  ルート検査が区切り境界を見ない前方一致なので、`C:\os32` をルートにすると
  `C:\os32-other` 以下が通る。**別リポジトリ**なのでビルドと配備が要る。
  OS32 側は `\` を含む要素の拒否で緩和済み (H1 の B1) だが、これは修正ではない。

## 4. 受入の考え方

各項目に、**変異で落ちるホスト試験**を付ける。とくに B8 は
「stat が `NOTFOUND` を返し、`get_file_size` は成功する」組み合わせを直接駆動すること
(H1 の追加試験はこの組み合わせを覆っていなかったため、往復 5 まで検出できなかった)。
