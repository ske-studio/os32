# V86サブシステム — 実装状況と設計方針

> 最終更新: 2026-05-15
> 目標: MS-DOS起動 → DOSネイティブアプリ / PC-98ネイティブソフトの動作

---

## 1. アーキテクチャ概要

OS32カーネル (i386プロテクトモード) 上で x86 Virtual 8086 Mode を利用し、
リアルモード16bitソフトウェアを実行する。

```
┌─────────────────────────────────┐
│  V86ゲスト (リアルモード16bit)  │  ← DOS / ゲーム / IPL
├─────────────────────────────────┤
│  #GP ハンドラ (v86.c)          │  ← 特権命令エミュレーション
│  I/O仮想化レイヤ               │  ← PIC/PIT/FDC/DMA/VSYNC/KBD
│  BIOS エミュレーション          │  ← INT 18h/1Bh/1Ch/11h/12h/29h
│  メモリ管理 (v86_mem.c)        │  ← バッキングRAM + ページング
├─────────────────────────────────┤
│  OS32 カーネル (Ring 0)        │
└─────────────────────────────────┘
```

### ソースファイル構成

| ファイル | 役割 |
|---------|------|
| `v86.c` | #GPハンドラ (命令デコード・I/Oディスパッチ・IRQ注入) |
| `v86.h` | コンテキスト構造体・レジスタインデックス・公開API |
| `v86_entry.asm` | IRETD によるV86モード遷移 |
| `v86_mem.c/h` | バッキングRAM確保・ページテーブル・IVT/BDA構築・画面初期化 |
| `v86_session.c/h` | セッションライフサイクル (ブート・Auto-Typer・終了処理) |
| `v86_bios.c/h` | INT 18h/29h/1Ch/11h/12h BIOSエミュレーション |
| `v86_disk.c/h` | INT 1Bh ディスクBIOS (loop_dev/実FDDバックエンド) |
| `v86_pic.c/h` | 8259A PIC仮想化 (マスタ/スレーブ) |
| `v86_pit.c/h` | 8253A PIT仮想化 (Counter#0-2) |
| `v86_fdc.c/h` | µPD765A FDCポートレベル仮想化 |
| `v86_dma.c/h` | µPD8237A DMA ch2 仮想化 |

## 2. CPUエミュレーション (#GPハンドラ)

V86モード (IOPL=0) では特権命令実行時に #GP が発生し、`v86_gp_handler()` で
命令をデコード・エミュレーションする。

### 2.1 対応済み命令

| 命令 | オペコード | 実装状況 |
|------|-----------|---------|
| INT n | 0xCD nn | ✅ IVT参照・BIOS割り込み分岐 |
| CLI | 0xFA | ✅ 仮想IFクリア |
| STI | 0xFB | ✅ 仮想IFセット |
| PUSHF | 0x9C | ✅ 仮想EFLAGS push |
| POPF | 0x9D | ✅ 仮想EFLAGS pop |
| PUSHFD | 0x66 0x9C | ✅ 32bit EFLAGS push |
| POPFD | 0x66 0x9D | ✅ 32bit EFLAGS pop |
| IRET | 0xCF | ✅ V86内割り込みリターン |
| HLT | 0xF4 | ✅ 終了要求時にV86停止、通常はNOP |
| IN AL,imm8 | 0xE4 | ✅ 仮想化チェック付き |
| IN AL,DX | 0xEC | ✅ 同上 |
| IN AX,imm8 | 0xE5 | ✅ 16bit I/O |
| IN AX,DX | 0xED | ✅ 同上 |
| OUT imm8,AL | 0xE6 | ✅ 仮想化チェック+リブート検知 |
| OUT DX,AL | 0xEE | ✅ 同上 |
| OUT imm8,AX | 0xE7 | ✅ 16bit I/O |
| OUT DX,AX | 0xEF | ✅ 同上 |
| INSB/INSW | 0x6C/0x6D | ✅ REP対応 |
| OUTSB/OUTSW | 0x6E/0x6F | ✅ REP対応 |

### 2.2 対応済みプレフィックス

0x66 (オペランドサイズ), 0x67 (アドレスサイズ), セグメントオーバーライド,
0xF0 (LOCK), 0x9B (FWAIT), 0xF3 (REP), 0xF2 (REPNE)

### 2.3 未対応・要対応

| 項目 | 状況 | MS-DOS動作への影響 |
|------|------|-------------------|
| INSD/OUTSD (32bit文字列I/O) | ❌ 未実装 | 低 (DOSでは稀) |
| LOCK付きメモリ操作 | ⚠️ LOCKプレフィックスは読み飛ばし | 低 |
| 0x0F 2バイトオペコード | ❌ 未実装 | 要調査 (LGDT/LIDT等がDOSエクステンダで必要) |

## 3. I/Oポート — パススルー vs 仮想化の分類

### 3.1 完全仮想化 (実ハードウェアに一切アクセスしない)

OS32カーネルの動作を保護するため、ゲストからの操作を仮想レジスタに記録し、
実ハードウェアには触れない。

| デバイス | ポート | 理由 |
|---------|--------|------|
| **マスタPIC** | 0x00, 0x02 | OS32のIRQルーティングを保護。ICW/OCW/EOI/IMR全て仮想化 |
| **スレーブPIC** | 0x08, 0x0A | 同上 |
| **PIT Counter#0** | 0x71 (データ), 0x77 (コマンド) | OS32の100Hzタイマを保護。ゲスト設定は分周比計算に使用 |
| **PIT Counter#2** | 0x75 | RS-232Cボーレート保護 |
| **FDC** | 0x90, 0x92, 0x94 | ディスクイメージ経由。4フェーズステートマシンで完全エミュレーション |
| **DMA ch2** | 0x09, 0x0B, 0x15, 0x17, 0x19, 0x23 | FDCバックエンドと連携。実DMAは使用しない |
| **キーボード 8251A** | 0x41 (データ), 0x43 (ステータス) | OS32がキーボードを管理。スキャンコードバッファ経由 |
| **リセットポート** | 0xF0 | V86終了トリガーとして使用 |

### 3.2 条件付き仮想化 (読み取りのみ仮想化、または部分仮想化)

| デバイス | ポート | 方式 |
|---------|--------|------|
| **テキストGDCステータス** | 0x60 (R) | ネイティブモード時: VSYNCビット(bit5)をGPカウントベースでトグル。DOSモード時: 実ハードウェア読み取り |
| **グラフィックGDCステータス** | 0xA0 (R) | 同上 |
| **VSYNC割り込みトリガ** | 0x64 (W) | armedフラグをセット。タイマIRQ経由で50Hz周期のINT 0Ah注入 |
| **PIT Counter#1 (ビープ)** | 0x73 | 仮想レジスタに記録 **かつ** 実ハードウェアにもパススルー |

### 3.3 直接パススルー (IOビットマップで許可)

ゲストが直接ハードウェアにアクセスする。GPフォルトは発生しない。

| デバイス | ポート | 備考 |
|---------|--------|------|
| **テキストGDCコマンド/パラメータ** | 0x62, 0x66, 0x68, 0x6A | ただし0x60(ステータス)と0x64(VSYNC)はトラップ |
| **CRTC** | 0x70, 0x72, 0x74, 0x76, 0x78, 0x7A | PITポート(奇数)はトラップ維持 |
| **GRCG** | 0x7C, 0x7E | |
| **グラフィックGDC (データ/コマンド)** | 0xA1-0xAE (0xA0除く) | 0xA0はVSYNCステータス仮想化のためトラップ |
| **EGC** | 0x04A0-0x04AE | |
| **FM音源 (OPN)** | 0x0188, 0x018A, 0x018C, 0x018E | Ys等のFM音楽再生に必須 |
| **ビープ制御** | 0x37 | |
| **I/Oウェイト** | 0x5F | FM音源レジスタ間ウェイトに使用。パススルー必須 |
| **カレンダ** | 0x20 | |
| **ページフリッピング** | 0xA4, 0xA6 | |

### 3.4 保護ポート (ゲストからのアクセスを無視)

| デバイス | ポート | 理由 |
|---------|--------|------|
| **HostDrv** | 0x7EC, 0x7EE | ゲストが書き込むとOS32のファイルI/O破損 |
| **RS-232C** | 0x30, 0x32, 0x33, 0x35, 0x75, 0x77 | 通信設定保護 (rshell用) |

## 4. メモリマップ

### 4.1 V86アドレス空間 (1MB)

| 仮想アドレス | 物理マッピング | アクセス権 | 用途 |
|-------------|---------------|-----------|------|
| 0x00000-0x8EFFF | backing+0 〜 backing+0x8EFFF | R/W/User | コンベンショナルメモリ (バッキングRAM) |
| 0x8F000-0x9FFFF | backing+0x8F000 〜 | R/W/User | カーネルスタック分離 |
| 0xA0000-0xA3FFF | 0xA0000 (実物理) | R/W/User | TVRAM |
| 0xA4000-0xA7FFF | 0xA4000 (実物理) | R/O/User | CGウィンドウ |
| 0xA8000-0xBFFFF | 0xA8000 (実物理) | R/W/User | GVRAM Plane B/R/G |
| 0xC0000-0xDFFFF | 0xC0000 (実物理) | R/O/User | 拡張ROM BIOS |
| 0xE0000-0xE7FFF | 0xE0000 (実物理) | R/W/User | GVRAM Plane E |
| 0xE8000-0xEFFFF | 0xE8000 (実物理) | R/O/User | 拡張ROM/バンクメモリ |
| 0xF0000-0xFFFFF | 0xF0000 (実物理) | R/O/**Supervisor** | BIOS ROM (**V86実行不可** — §13参照) |

### 4.2 バッキングRAM

- pgalloc から連続160ページ (640KB) を動的確保
- V86セッション終了時に全ページ解放
- カーネルスタック (0x8F000-0x9FFFF) はバッキングRAMにコピー→リマップで分離

### 4.3 BDA初期値

IVT (256ベクタ → ダミーIRETハンドラ 0x003F:0x0000)、BDA各フィールド
(メモリサイズ640KB, CPU=i386, FDD UNIT#0接続, ブートデバイス=0x90 等) を構築。

## 5. 割り込み仮想化

### 5.1 仮想IFフラグ

CLI/STI は `v86_virtual_if` を操作し、実EFLAGSのIFは変更しない。
仮想IF=1 かつ保留IRQがある場合、GPハンドラ末尾でIVT経由注入。

### 5.2 IRQ注入

| IRQ | INT | 注入方式 | 実装状況 |
|-----|-----|---------|---------|
| IRQ0 (タイマ) | 08h | HW直接注入 (timer_handler) + GP保留注入 | ✅ PIT分周比反映済み |
| IRQ1 (キーボード) | 09h | GP保留注入 (v86_kbd_enqueue経由) | ✅ スキャンコードバッファ |
| IRQ2 (VSYNC) | 0Ah | HW直接注入 (50Hz, ワンショット) | ✅ armed方式 |

### 5.3 ISR管理

仮想ISRでサービスビットを管理。ゲストのEOI (OCW2) で仮想ISRクリア。
ISRスタック防止: 100tick無EOIで自動クリア。

## 9. カーネルメモリマップとA20ラップアラウンド

### 9.1 カーネル0x110000スライド (2026-05-14)

カーネルロードアドレスを `0x100000` → `0x110000` に移動し、
`0x100000-0x10FFFF` (64KB) をA20ラップ用に予約した。

**変更ファイル:**

| ファイル | 変更内容 |
|---------|---------|
| `include/memmap.h` | `KERNEL_LOAD_ADDR` = `0x110000UL` |
| `build/os32.ld` | `. = 0x110000;` |
| `build/kernel.mk` | `--kernel-addr 0x110000` |
| `boot/loader_hdd.asm` | `JMP FAR 0008:00110000h` |
| `boot/loader_fat_new.asm` | 同上 |

**注意**: カーネルBSSが `0x169280` まで伸び、KHEAP〜SHM配置は
`0x16A000-0x1FD000` に収まる (0x200000 SQLite帯域との衝突なし)。

### 9.2 A20ラップアラウンド — 試行と制約

V86モードではA20ラインが有効なため、リアルモードの1MB境界ラップが発生しない。
BIOSコードの一部は `CS=FD80` 等の高セグメントで `IP` が進むと
リニアアドレスが 0x100000 を超え、A20=0 の折り返しに依存している。

#### 試行1: #PFベースCSリワインド (失敗)

カーネルが `0x100000` にあった時代の方式。
0x100000+ へのV86アクセスで #PF を発生させ、ハンドラ内で
`CS -= 0x1000` して20bitラップを再現しようとした。

**失敗原因**: NP21/Wの CPUエミュレータがPTEの U/S ビットチェックを
正しく行わず、V86 (Ring 3) がカーネルコード領域 (PTE_USER なし) を
直接実行できてしまう。#PF が発生せず、カーネルバイナリのバイト列が
そのまま命令として実行される。

#### 試行2: PTEリマップ方式 (失敗)

カーネルを `0x110000` にスライドし、空いた `0x100000-0x10FFFF` を
バッキングRAMの `0x00000-0x0FFFF` にPTEリマップする方式。

```c
/* v86_mem_setup() 内 */
for (addr = 0x100000; addr < 0x110000; addr += PAGE_SIZE) {
    u32 wrap_phys = v86_backing_phys + (addr - 0x100000);
    paging_set_page(addr, wrap_phys, PTE_PRESENT | PTE_RW | PTE_USER);
}
```

**失敗原因**: NP21/Wのページングエミュレーションと衝突し、
V86モード進入直後にトリプルフォルトが発生する。
原因の切り分けにより、リマップコードを `#if 0` で無効化すると
トリプルフォルトが解消されることを確認済み。

**検証結果:**
- A20リマップあり → トリプルフォルト (`CR2=0x4F8, VM=1`)
- A20リマップなし → V86正常動作 (FDCタイムアウトまで進行)

#### 現在の状態

A20リマップは `#if 0` で無効化済み (v86_mem.c)。
カーネルは `0x110000` に配置されているため、V86が `0x100000+` を
実行しても**カーネルコードが実行されることはなくなった** (主目的は達成)。
ただし正しいA20折り返しは行われない。

### 9.3 NP21/W固有の制約

| 制約 | 影響 | 回避策 |
|------|------|--------|
| PTE U/S ビット無視 | V86がsupervisorページを直接実行可能 | カーネルを0x110000に移動して衝突回避 |
| PTEリマップ非対応? | 0x100000帯のPTE変更後にトリプルフォルト | リマップを使わない |
| PDE USER=1 時に PTE USER も要求 | IDT/TSS/ISR領域に PTE_USER がないとトリプルフォルト | カーネル帯 (0x110000-0x16FFFF) に PTE_USER を付与 |

## 10. MS-DOS起動に向けた課題

### 10.1 トリプルフォルト — 根本原因特定 (2026-05-15)

**確定した根本原因**: GP ハンドラの INT 処理パスで、既存 HLE (INT 18h/1Ch/11h/12h)
を使用せず IVT 転送で BIOS ROM (FD80:xxxx) に直接ジャンプしていた。
ROM 内コード実行中にカーネル自身が #PF を起こしトリプルフォルトに至る。

**調査経緯:**

| 日時 | 仮説 | 結果 |
|------|------|------|
| 05-14 | FDCポーリングハング | ⚠️ 一因だが根本ではない |
| 05-15 AM | PTE/IVT/IPL の不整合 | ❌ 全て正常 (DIAG確認) |
| 05-15 AM | IRQ介入 (_enable/_disable) | ❌ 無効化しても再現 |
| 05-15 PM | **BIOS ROM 直接実行** | ✅ **確定** |

**決定的証拠 (GPシリアルトレース):**
```
GP#1: 1FC0:015A  INT 1Bh   SS:SP=0:0286  ← IPL (HLE処理)
GP#2: FD80:0017  CLI       SS:SP=0:0280  ← BIOS ROM内!
GP#3: FD80:001C  IN AL,35h SS:SP=0:0280  ← BIOS ROM I/O
                                          ← この直後にトリプルフォルト
```

**PFシリアルトレース:**
```
[V86-PF] addr=0x800166FD err=0x02 eip=0x00000000 CS=0x0008
```
- CS=0x0008 = **カーネルCS** → V86ではなくカーネル自身が #PF
- addr=0x800166FD = 壊れたポインタ (2GB付近)

**メカニズム:**
1. IPL が INT N を実行 → GP ハンドラが IVT[N] を参照
2. IVT[N] = FD80:xxxx (BIOS ROM) → IVT 転送で ROM にジャンプ
3. ROM コード (CLI/IN/OUT等) が #GP 経由でエミュレーション
4. ROM コードの後続命令が未エミュレーション領域にアクセス
5. カーネル内で #PF 発生 → #DF → トリプルフォルト

### 10.2 解決策: 方法 C — BIOS ROM 実行排除 (§13 参照)

2層防御で BIOS ROM の V86 実行を完全に排除する:
- **Layer 1**: GP ハンドラで ROM 行き IVT 転送をインターセプト → HLE 呼び出し
- **Layer 2**: ROM ページの PTE_USER 除去 → V86 から実行不可

これにより ROM 内の複数 #GP ラウンドトリップも排除され、
オーバーヘッドは現状より**減少**する (5+ #GP/call → 1 #GP + HLE)。

### 10.3 旧: FDCポーリングハング (2026-05-14)

> [!NOTE]
> §10.1 の ROM 実行排除により、BIOS ROM 内 FDC ルーチンは実行されなくなる。
> FDC ポーリングハングは INT 1Bh HLE が直接処理するため、本問題は自動的に解消される見込み。
> ただし FDC ポートレベル仮想化 (§7) は FORMAT.COM 等の直接アクセスに引き続き必要。

### 10.4 必要な追加実装 (優先度順)

| # | 項目 | 説明 | 優先度 |
|---|------|------|--------|
| 1 | **BIOS ROM 実行排除 (§13)** | 方法 C の実装。GP ハンドラでの ROM 行き IVT インターセプト | **最高** |
| 2 | **既存 HLE の GP ハンドラ接続** | INT 18h/1Ch/11h/12h の HLE が存在するが GP ハンドラで呼ばれていない | **最高** |
| 3 | **INT 21h DOSファンクション** | DOSカーネル自体が処理するため基本的にエミュレーション不要 | 情報 |
| 4 | **HDD (INT 1Bh DA=A0h)** | HDDイメージからのDOSブート | 中 |
| 5 | **A20ラップの完全実装** | NP21/Wの制約を回避する別方式の検討 | 低 |
| 6 | **EMSメモリ管理** | DOS上のEMSドライバ対応 | 低 |

### 10.4 パススルー設計の原則

1. **OS32が使用中のデバイス → 完全仮想化**
   - PIC: OS32のIRQルーティングを保護
   - PIT Counter#0: OS32の100Hzタイマを保護
   - キーボード: OS32がスキャンコード読み取りを管理
   - RS-232C: rshellのシリアル通信を保護
   - HostDrv: ファイルシステムI/Oを保護

2. **ゲスト専用デバイス → 直接パススルー**
   - FM音源: レイテンシが重要。仮想化のGPオーバーヘッドは許容不可
   - GVRAM/TVRAM: メモリマップドI/Oとしてページテーブルで直接許可
   - GDCコマンド: テキスト/グラフィック制御
   - GRCG/EGC: グラフィック描画アクセラレータ

3. **状態監視が必要なデバイス → 条件付き仮想化**
   - GDCステータス (VSYNCビット): ゲームのVSYNC同期に必要
   - PIT Counter#1 (ビープ): 仮想レジスタ記録 + 実ハードウェアパススルー
   - FDC: ディスクイメージの場合は完全仮想化、実FDDの場合はパススルー

## 12. 既知の問題: §BUG-CTX (v86_enter 直前の ctx 破壊)

### 12.1 症状

`kernel/v86_session.c:254` で確保されたローカル変数 `struct v86_context ctx` が、L260 で `ctx.eip = 0x0000` に初期化された後、L495 の `v86_enter(&ctx)` に到達するまでの間にスタック上で破壊される。

**GCCビルドでの ctx 配置** (objdump 解析済み):
- スタックフレーム: `sub $0x4c, %esp` (76バイト)
- ctx は `EBP-0x3C` 〜 `EBP-0x1C` に配置 (36バイト = 9 × u32)
- カーネルスタック: `0x90000-0x9FFFF` (64KB, memmap.h)
- ※ 旧観測アドレス `~0xEFF6xx` は OpenWatcom 時代の値。GCC ビルドでは異なる

**観測値**: `ctx.eip = 0x0014` (本来 0x0000)。
- 0x0014 = 20。`struct v86_context` 的なオフセット 20 は `es` フィールドの位置。
- 破壊位置の特定にも、化けた値の出処にも、まだ手がかりが揃っていない。

### 12.2 発生条件

L260 から L495 の間で実行される以下の処理経路で発生する。

- TSS ESP0 切替 (`tss_set_esp0`)
- FM 音源 / EGC 状態退避
- SSG レジスタ初期化 (大量の `outp` + `io_wait`)
- メモリスイッチ SW4 / サウンド BIOS ROM 確認
- 各種 `kprintf` (PIC IMR、tick、CR3/PDE/PTE、IDT/ESP0 ダンプ等)
- TLB フラッシュ (CR3 リロード)

### 12.3 現状のホットフィックス (無効化中)

`kernel/v86_session.c:470-494` に `#if 0` ガード付きで「`v86_enter` 直前に ctx を再代入する」ブロックが残されている。再有効化すれば一時的な動作は復活するが、根本原因は未特定。コメントには `§BUG-CTX ホットフィックス無効化: 初回設定(L260)のみでテスト` と記載されている。

### 12.4 原因候補 (確度推定順)

1. **kprintf 群がスタックバッファをオーバーフロー** している可能性。L401-458 の CR3/PDE/PTE/IDT ダンプは複数の長い書式文字列を渡しており、内部バッファのサイズが ctx の領域に届く可能性がある。
2. **TSS ESP0 切替後の Ring0 割り込み** との競合。L273 で TSS の `esp0` を `v86_kstack` に切り替えた後、現在の実行スタックとの整合が崩れる経路が存在しうる。
3. ~~`v86_enter` の呼び出し規約ミスマッチ~~ — **GCC移行により除外**。GCC (System V i386 ABI) ではスタック渡し (`cdecl`) がデフォルトであり、`v86_entry.asm` の `[esp+4]` と一致する。GCCビルドでも再現が確認されたため、呼び出し規約の不整合は原因ではない。
4. ~~`struct v86_context` のアライメント / レイアウト~~ — **GCC移行により除外**。GCC のデフォルトパッキングでは `sizeof(struct v86_context)` = 36 (9 × `u32`、パディングなし)。asm 側オフセット (0/4/8/12/16/20/24/28/32) と整合する。
5. **`v86_kstack` 配列と `ctx` ローカルのメモリ配置近接**。ESP 切替時に v86_kstack 領域への書き込みが ctx 領域に届く可能性。

### 12.5 調査結果・最終結論 (2026-05-15)

以下の仮説は全て **否定** された:

| 仮説 | 結果 |
|------|------|
| ctx スタック破壊 | ❌ static 化しても同一クラッシュ |
| kprintf のスタック消費 | ❌ 無効化/復元どちらでも同一クラッシュ |
| ctx フィールド値の破壊 | ❌ v86_enter 直前の診断で全フィールド正常確認 |
| PTE/IVT/IPL の不整合 | ❌ 全て正常 (DIAG確認) |
| IRQ 介入 (_enable/_disable) | ❌ 無効化しても再現 |

**根本原因を特定**: §BUG-CTX は ctx 破壊ではなく、**BIOS ROM の V86 直接実行**
が原因であった (§10.1 参照)。GP ハンドラが既存 HLE を呼ばず IVT 転送で BIOS ROM に
ジャンプ → ROM 内コードがカーネル #PF を誘発 → トリプルフォルト。

確定事実: クラッシュは 100% 決定的 (`cs=0 eip=4F8 cr2=4F8 esp=27E`)。

## 13. BIOS ROM 実行排除 — 方法 C アーキテクチャ変更

> 追記: 2026-05-15 — トリプルフォルト根本原因の解決策

### 13.1 設計変更の概要

**変更前 (ハイブリッド方式)**:
- IVT に BIOS ROM ベクタ (FD80:xxxx) を設定
- V86 コードが INT → IVT 転送 → BIOS ROM 内コードが V86 で直接実行
- ROM 内の I/O 命令は #GP 経由で仮想化ディスパッチャが処理
- **問題**: ROM 内の非特権命令が未対応のメモリ/状態にアクセスしトリプルフォルト

**変更後 (完全 HLE 方式)**:
- IVT の ROM ベクタは維持 (BDA 互換性)
- GP ハンドラの INT パスで ROM 行き IVT を自動検出・インターセプト
- 既存 HLE で処理、未 HLE 化 INT は CF=1/AH=0x86 フォールバック
- BIOS ROM ページは PTE_USER 除去 (セーフガード)
- **ROM コードは一切 V86 モードで実行されない**

### 13.2 2層防御

| Layer | 場所 | 処理 |
|-------|------|------|
| **Layer 1** (主防御) | `v86.c` GPハンドラ INT パス | IVT handler_seg >= 0xF000 を検出 → HLE 呼び出し or CF=1 フォールバック |
| **Layer 2** (セーフガード) | `v86_mem.c` PTE 設定 | ROM ページ (0xF0000-0xFFFFF) から PTE_USER 除去 → V86 実行不可 |

### 13.3 直接 BIOS ROM アクセスコードのパージ計画

方法 C 実装に伴い、BIOS ROM に V86 が直接ジャンプする前提のコードを段階的にパージする。

#### パージ対象

| ファイル | 対象コード | 理由 |
|---------|-----------|------|
| `v86_mem.c` L190-218 | BIOS ROM ベクタテーブルからの IVT 設定 | ROM ベクタは IVT に設定しても Layer 1 で阻止される。ダミー IVT (003F:0000) で十分 |
| `v86_mem.c` L500-503 | BIOS ROM ページの `PTE_PRESENT \| PTE_USER` 設定 | `PTE_PRESENT` のみに変更 (Layer 2) |
| `v86.c` L746-748 | 「ROM内コードが#GPで仮想化される」旨のコメント | 方式変更に合わせてコメント更新 |
| `v86_session.c` DIAG コード | ROM ダンプ / IPL ダンプ / PTE 診断 | 調査完了のため削除 |
| `isr_handlers.c` | V86 #PF シリアルトレース | 調査完了のため削除 |
| `v86.c` | GP#1-10 シリアルトレース | 調査完了のため削除 (通常トレース機構に戻す) |

#### パージ判断保留

| ファイル | 対象コード | 保留理由 |

| `v86_session.c` L308 | `BIOS_ROM` 終了条件 (`CS >= 0xF000`) | Layer 1 が機能すれば到達しないが、安全弁として当面残す |

#### パージしない

| ファイル | 対象コード | 残す理由 |

| `v86.c` の I/O ディスパッチ全体 | IN/OUT エミュレーション | ROM 経由ではなく V86 ゲストコード自体の I/O に引き続き必要 |
